# Live Events v2 — Инструкция по тестированию для сотрудника

> **Версия**: 2026-04-10  
> **Аудитория**: сотрудники, тестировщики (не разработчики)  
> **Важно**: тестирование проводится ТОЛЬКО на тестовых аккаунтах

---

## ⚠️ ЗАПРЕЩЕНО (красная зона)

> **Нарушение любого из этих правил может привести к рассылке реальным клиентам.**

1. ❌ **НЕ использовать боевые эфиры** (особенно эфир `3dc1c789`) для тестирования
2. ❌ **НЕ включать `production_approved=true`** без явного согласования с руководителем
3. ❌ **НЕ включать `enabled=true`** в live_notification_config без согласования
4. ❌ **НЕ активировать pg_cron job** (планировщик)
5. ❌ **НЕ отправлять уведомления реальным клиентам** — ни через Telegram, ни через Email
6. ❌ **НЕ менять test_allowlist** самостоятельно — только через согласование
7. ❌ **НЕ использовать `dispatch_mode=production`** при тестировании

---

1. ✅ Создавать тестовые эфиры (новые, с пометкой «ТЕСТ»)

7. ✅ Проверять `/live` и `/live/:slug` под тестовым аккаунтом
8. ✅ Писать комментарии/вопросы под тестовым аккаунтом
9. ✅ Отправлять ответы (replies) на тестовых эфирах

## Шаг 1. Создание тестового эфира

1. Перейти в **Админка → Эфиры**
2. Нажать **«Создать эфир»**
3. Заполнить:
   - Название: `ТЕСТ — [ваше имя] — [дата]`
   - Тип: **Живой эфир**
   - Slug: `test-[дата]`
   - Дата/время: на 2 часа вперёд от текущего момента
   - Часовой пояс: Europe/Minsk
4. Сохранить эфир

---

## Шаг 2. Создание источника Kinescope

1. В карточке тестового эфира найти блок **«Источник»**
2. Выбрать папку Kinescope (тестовую)
3. Нажать **«Создать источник»**
4. Дождаться появления данных OBS (RTMP URL + Stream Key)
5. Проверить, что `provider_source_status = active`

---

## Шаг 3. Настройка доступа

1. В карточке эфира перейти в **«Доступы»**
2. Добавить правило доступа:
   - Product: тестовый продукт
   - Tariff: (опционально)
3. Убедиться, что тестовый аккаунт имеет подписку на этот продукт

---

## Шаг 4. Проверка уведомлений (ТОЛЬКО safe-mode)

### 4.1 Dry-run (без отправки)

1. Настроить `notification_settings` в тестовом эфире:
   - Включить уведомления
   - Выбрать шаблон
   - Выбрать канал (Telegram)
   - Выбрать offset (за 1 час)
2. Попросить разработчика выполнить вызов cron с `dry_run=true`
3. Проверить ответ:
   - Должен показать аудиторию и рендер текста
   - НЕ должен отправить сообщения

### 4.2 Proof-отправка (на test_allowlist)

> Только после согласования!

1. Убедиться, что ваш user_id добавлен в `test_allowlist`
2. Убедиться, что `proof_mode=true`
3. Убедиться, что `production_approved=false`
4. Попросить разработчика выполнить вызов с соответствующими параметрами
5. Проверить получение сообщения в Telegram

---

## Шаг 5. Проверка /live (список эфиров)

1. Открыть `/live` под тестовым аккаунтом
2. Проверить:
   - [ ] Тестовый эфир виден в списке
   - [ ] Название, описание, дата отображаются корректно
   - [ ] Статус эфира отображается правильно
   - [ ] Кнопка перехода к эфиру работает

---

## Шаг 6. Проверка /live/:slug (страница эфира)

1. Перейти на `/live/[slug-тестового-эфира]`
2. Проверить:
   - [ ] Страница загружается
   - [ ] Плеер отображается (или placeholder до начала)
   - [ ] Заголовок и описание корректны
   - [ ] Статус эфира (scheduled → live → completed) отображается

---

## Шаг 6a. Проверка layout (desktop и mobile)

### Desktop
1. Открыть `/live/:slug` на desktop (ширина > 1024px)
2. Проверить:
   - [ ] Видео-область занимает основную часть экрана (примерно 2/3)
   - [ ] Колонка чата/вопросов видна справа
   - [ ] Поле ввода комментария зафиксировано внизу
   - [ ] Вкладки «Чат / Вопросы» доступны
   - [ ] CTA-блоки (под видео и в сайдбаре) не ломают layout

### Mobile
3. Открыть `/live/:slug` на mobile (или уменьшить окно < 768px)
4. Проверить:
   - [ ] Видео отображается вверху на полную ширину
   - [ ] Вкладки «Чат / Вопросы» зафиксированы (sticky)
   - [ ] Поле ввода зафиксировано внизу (sticky), с учётом safe-area
   - [ ] Нет лишних вертикальных отступов
   - [ ] CTA-блоки не перекрывают контент

---

## Шаг 7. Проверка комментариев, вопросов и отображения авторов

1. На странице `/live/:slug`:
   - [ ] Написать тестовый комментарий
   - [ ] Комментарий появился в ленте
   - [ ] **Имя автора** отображается корректно (не «Пользователь»)
   - [ ] Написать тестовый вопрос ведущему
   - [ ] Вопрос отображается в панели вопросов
2. В админке:
   - [ ] Комментарии видны в контрольной панели
   - [ ] Вопросы видны в контрольной панели

### Проверка role badges
3. Под аккаунтом **admin**:
   - [ ] Написать комментарий — отображается бейдж «Админ» (фиолетовый/индиго)
4. Под аккаунтом **employee** (если есть):
   - [ ] Написать комментарий — отображается бейдж «Сотрудник»
5. Под обычным аккаунтом:
   - [ ] Бейдж роли НЕ отображается

### Проверка имён (snapshot)
6. Написать комментарий от аккаунта с заполненным `full_name`
   - [ ] Имя соответствует `full_name` из профиля
7. Если есть старые записи без snapshot:
   - [ ] Имя подтягивается через fallback из профиля

---

## Шаг 7a. Проверка ответов (replies)

### Из комнаты (inline)
1. На `/live/:slug` навести на комментарий (под staff-аккаунтом):
   - [ ] Появляется кнопка «Ответить»
   - [ ] Написать **публичный** ответ → виден всем пользователям
2. Навести на вопрос:
   - [ ] Написать **приватный** ответ → виден только автору вопроса и админу
   - [ ] Другие пользователи **не видят** приватный ответ

### Из админки
3. В админке открыть комментарий → «Ответить»:
   - [ ] Публичный ответ виден на `/live/:slug`
4. Открыть вопрос → «Ответить»:
   - [ ] Приватный ответ виден только автору и админу

---

## Шаг 7b. Проверка модерации (inline + админка)

### Inline moderation (из комнаты)
1. На `/live/:slug` под staff-аккаунтом навести на сообщение:
   - [ ] Кнопка **удалить сообщение** — работает, сообщение скрывается
   - [ ] Кнопка **mute** — работает, пользователь не может отправлять сообщения
   - [ ] Кнопка **unmute** — работает, пользователь снова может писать
2. Под admin-аккаунтом:
   - [ ] Кнопка **удалить из комнаты** — работает
   - [ ] Кнопка **восстановить** — работает
3. Под employee-аккаунтом:
   - [ ] Кнопки «удалить из комнаты» и «восстановить» **НЕ отображаются**
4. **Открытие карточки пользователя**:
   - [ ] Нажать на имя/аватар пользователя → открывается карточка контакта (Contact Sheet)

### Негативный сценарий (обязательный)
5. Удалить тестового пользователя из комнаты
6. Под удалённым аккаунтом проверить:
   - [ ] `/live/:slug` — **не может** открыть страницу (или видит блокировку)
   - [ ] **Не может** отправить комментарий
   - [ ] **Не может** отправить вопрос
7. Восстановить пользователя → проверить восстановление доступа

---

## Шаг 7c. Проверка legacy room blocks

> **Примечание**: legacy room blocks сохранены для обратной совместимости. При наличии product CTA на той же позиции — legacy блок подавляется (см. Шаг 7g).

1. В админке перейти во вкладку **«Блоки»**
2. Создать **button-блок** (`live_only`, позиция `under_video`):
   - [ ] Блок виден на `/live/:slug` когда эфир `live`
   - [ ] Блок **не виден** когда эфир `completed` (replay)
3. Создать **banner-блок** (`replay_only`, позиция `sidebar`):
   - [ ] Блок **не виден** когда эфир `live`
   - [ ] Блок виден когда эфир `completed` (replay)
4. Создать блок с `display_scope = always`:
   - [ ] Виден и в live, и в replay

---

## Шаг 7d. Проверка сценария

1. В админке открыть тестовый эфир → вкладка **«Сценарий»**
2. Проверить:
   - [ ] Таймлайн содержит комментарии
   - [ ] Таймлайн содержит вопросы
   - [ ] Таймлайн содержит ответы (replies)
   - [ ] Таймлайн содержит действия модерации
   - [ ] Таймлайн содержит **CTA events** (показ/скрытие/клики) — если CTA настроен
   - [ ] Фильтры по типу событий работают корректно

---

## Шаг 7e. Проверка имён авторов

### Snapshot (новые записи)
1. Написать комментарий/вопрос от тестового аккаунта с заполненным именем
2. Проверить:
   - [ ] Имя автора отображается корректно (не «Пользователь»)
   - [ ] Имя соответствует `full_name` из профиля

### Legacy fallback (старые записи)
3. Если есть старые записи без snapshot:
   - [ ] Имя подтягивается через fallback из профиля
   - [ ] Не показывается «Пользователь» там, где есть `full_name`

---

## Шаг 7f. Проверка CRM pipeline (цепочка)

> Этот шаг проверяет, что активность пользователя в вебинаре корректно попадает в CRM.

1. Выполнить действие (комментарий, вопрос, reply или модерацию)
2. Подождать 1–2 минуты (время обработки consumer)
3. Проверить последовательно:
   - [ ] Запись появилась в `domain_events` (source = 'webinar')
   - [ ] Consumer обработал событие (запись в `domain_executions`, status = 'success')
   - [ ] Запись появилась в `crm_activity_log`
   - [ ] `idempotency_key` заполнен корректно
4. Повторный запуск consumer:
   - [ ] **Не создаёт дубль** в `crm_activity_log`

---

## Шаг 7g. Проверка Product CTA

> CTA привязывается к реальным продуктам/тарифам/офферам из каталога products_v2.

### Создание CTA binding
1. В админке открыть тестовый эфир → вкладка **«CTA»**
2. Нажать **«Добавить CTA»**
3. Выбрать:
   - Продукт (из products_v2)
   - Тариф (опционально)
   - Оффер (опционально, определяет цену)
   - Тип: `buy_now` / `open_product` / `open_tariff` / `external_link`
   - Позиция: `under_video` / `sidebar`
4. Проверить:
   - [ ] CTA появился в списке bindings
   - [ ] CTA отображается на `/live/:slug` в правильной позиции

### Проверка типов CTA
5. CTA с типом `buy_now`:
   - [ ] Нажатие открывает окно оплаты (PaymentDialog)
   - [ ] Цена соответствует цене из оффера (не хардкод)
6. CTA с типом `open_product`:
   - [ ] Переход на `/product/[slug]`
7. CTA с типом `external_link`:
   - [ ] Переход по внешней ссылке

### Проверка прав
8. Под **admin** аккаунтом:
   - [ ] Кнопки «Показать» / «Скрыть» CTA доступны
   - [ ] Кнопки «Добавить» / «Редактировать» / «Удалить» CTA доступны
9. Под **employee** аккаунтом:
   - [ ] Список CTA виден (read-only)
   - [ ] Кнопки управления CTA **НЕ отображаются** (ни show/hide, ни add/edit/delete)

### Проверка приоритета над legacy
10. Создать legacy room block на позиции `under_video`
11. Создать product CTA binding на позиции `under_video` (is_active=true)
12. Проверить на `/live/:slug`:
    - [ ] Отображается **только product CTA**
    - [ ] Legacy block **НЕ отображается** на этой позиции
13. Деактивировать product CTA (is_active=false)
14. Проверить:
    - [ ] Legacy block снова отображается

## Шаг 7h. Проверка темы комнаты

### Настройка темы
1. В админке открыть тестовый эфир → вкладка **«Тема»**
2. Задать цвета:
   - Фон: тёмный цвет (например, #1a1a2e)
   - Основной текст: светлый (например, #e0e0e0)
   - Акцент: яркий (например, #ff6b6b)
   - Бейдж админа: кастомный цвет
   - Бейдж сотрудника: кастомный цвет
3. Нажать **«Сохранить»**

### Проверка в комнате
4. Открыть `/live/:slug`:
   - [ ] **Фон комнаты** изменился на заданный цвет
   - [ ] **Основной текст** отображается заданным цветом
   - [ ] Бейджи ролей используют кастомные цвета (если заданы)

### ⚠️ Deferred: полная пропагация
5. Проверить вложенные элементы:
   - [ ] Панели (карточки чата) — применяется ли цвет панелей?
   - [ ] Вкладки (Чат / Вопросы) — применяется ли цвет вкладок?
   - [ ] Бейджи ролей — применяются ли кастомные цвета?
   
> **Если тема применяется НЕ ко всем элементам** — это известное ограничение (deferred). Зафиксировать, какие элементы не подхватили тему, и записать в отчёт как **deferred баг**, а не критический.

### Сброс темы
6. Нажать **«Сбросить»** → сохранить
   - [ ] Комната вернулась к стандартному оформлению

## Шаг 7i. Проверка Excel export

1. В админке открыть тестовый эфир → вкладка **«Сценарий»**
2. Нажать кнопку экспорта **«Комментарии»**:
   - [ ] Скачивается Excel-файл
   - [ ] Файл содержит комментарии с именами авторов и временными метками
3. Нажать кнопку экспорта **«Вопросы»**:
   - [ ] Скачивается Excel-файл
   - [ ] Файл содержит вопросы с именами авторов
4. Нажать кнопку экспорта **«Сценарий»**:
   - [ ] Скачивается Excel-файл
   - [ ] Файл содержит unified timeline: комментарии, вопросы, ответы, модерацию
   - [ ] Если был настроен CTA — файл содержит CTA events (показ/клик)
   - [ ] Метаданные CTA (продукт, тариф, тип) присутствуют в строках

## Шаг 7j. Проверка Webinar Activity в профиле

1. Выполнить действия в комнате (комментарий, вопрос, reply)
2. Подождать 1–2 минуты (обработка consumer)
3. В админке открыть карточку контакта (профиль тестового пользователя)
4. Проверить раздел **«События»** / **Webinar Activity**:
   - [ ] Записи о действиях в вебинаре отображаются
   - [ ] Тип действия корректен (комментарий, вопрос, ответ)
   - [ ] Привязка к эфиру корректна
   - [ ] Приватные ответы видны только персоналу

---

## Шаг 8. Проверка запуска и завершения

1. В админке нажать **«Запустить эфир»** (на тестовом эфире)
2. Проверить:
   - [ ] `platform_status` сменился на `live`
   - [ ] На `/live/:slug` статус обновился
3. Нажать **«Завершить эфир»**
4. Проверить:
   - [ ] `platform_status` сменился на `completed`
   - [ ] Кнопка «Обновить источник» доступна

---

## Шаг 9. Проверка recorded_webinar (регрессия)

> Этот шаг проверяет, что тип `recorded_webinar` не сломан после обновлений.

1. Найти или создать эфир типа **recorded_webinar**
2. Проверить:
   - [ ] Страница `/live/:slug` загружается
   - [ ] Видео отображается
   - [ ] Комментарии и вопросы работают
   - [ ] CTA отображается (если настроен)
   - [ ] Тема применяется (если задана)

---

## Шаг 10. Rollback / Очистка после теста

1. Снять публикацию с тестового эфира (`is_published = false`)
2. Удалить тестовые access_rules (или деактивировать)
3. Отключить notification_settings в тестовом эфире
4. Деактивировать тестовые CTA bindings (is_active = false)
5. **НЕ удалять сам эфир** — оставить для отчёта

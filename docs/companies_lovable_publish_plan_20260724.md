# CRM Companies — план синхронизации и публикации в Lovable

Документ нужен как единый чек-лист для публикации Companies-изменений после того, как очередь Lovable освободится. Публиковать только изменения CRM Companies; задачи вебинаров, мобильного `/cb`, авторизации и платёжной обработки не смешивать.

## 1. Синхронизация исходного кода

1. Убедиться, что Lovable подтянул `main` после merge commit `9b401c980027d5004a4511e9e4c156b684205c73` (PR #132).
2. Предыдущий Companies-патч уже находится в `main` после merge commit `bfebd3a6ecba137c525391cc9704aeb92f4841d5` (PR #130).
3. Проверить, что в `src/components/admin/ContactDetailSheet.tsx` карточка связанной компании является кнопкой и показывает только название.
4. Проверить, что `src/components/admin/communication/InboxTabContent.tsx` передаёт права Companies для открытия карточки суперадминистратором.

## 1a. Полный Companies-чеклист перед Publish

Это сводка всех согласованных Companies-изменений из текущего спринта. Пункты проверяются последовательно, а не смешиваются с вебинарами, мобильным `/cb`, авторизацией или платежной обработкой:

- каноническая таблица и визуальные паттерны Contacts: 100 строк, вертикальный скролл, горизонтальный overflow только при необходимости, сортировка, фильтры, календарь даты создания, выбор строк, колонки, экспорт/импорт и поиск по всей базе;
- верх страницы компактный: без блоков «Качество данных» и «Синхронизация реквизитов», таблица поднята к фильтрам;
- создание и редактирование юрлица/ИП переиспользуют существующую форму реквизитов с автозаполнением по УНП; без УНП остаётся ручное заполнение;
- название хранится и показывается без кавычек, длинной организационной формы и лишних служебных символов; форма собственности хранится отдельно и не выводится в имени строки;
- телефон нормализован в поле контакта компании (`+375...`) и запускает штатные Call/SMS-интеграции, а не отображается только справочным текстом;
- карточка компании повторяет размер, навигацию, ленту заметок, звонки/SMS/письма, сделки, задачи, доступы и профиль карточки контакта; дублирующие «Персоны» не создают отдельную сущность;
- из контакта открывается связанная компания, из компании — связанные контакты; строки задач с компанией открывают карточку компании, а не требуют ручного поиска;
- дата повторного звонка из импорта создаёт связанную задачу типа «Звонок» на Полину Асмaнту;
- импорт Google Sheets переносит название, email, телефон, заметку руководителя, найденные контакты и дату повторного звонка идемпотентно; повторный импорт не создаёт дубли;
- права `companies` доступны в настройках ролей с режимами чтения/изменения/удаления; superadmin может редактировать, остальные роли подчиняются своей матрице;
- глобальный поиск находит компанию в Companies, Contacts, Deals, Payments и контакт-центре, а связанные карточки открываются взаимно.

## 2. Managed Supabase

Применить через штатный Lovable/Supabase workflow миграцию:

`supabase/migrations/20260724105452_crm_cross_entity_company_search_20260724.sql`

Она добавляет поиск контактов по компании и расширяет серверный поиск в Contacts, Deals и глобальном поиске без изменения существующих RPC-контрактов и RLS.

После применения убедиться, что функция существует в schema cache:

`public.search_profile_ids_by_company(p_query text)`

Пока миграция не применена, фронтенд использует безопасный read-only fallback через `companies` → `company_contacts`; ошибка schema cache не должна показываться пользователю.

## 3. UI-публикация

1. Publish только Companies-патч.
2. Не отправлять реальные звонки, SMS или письма.
3. Не подтверждать и не публиковать посторонние задачи из очереди Lovable.

## 4. Авторизованный smoke-test после Publish

1. `/admin/communication?tab=inbox`: открыть контакт → «Компании» → нажать строку компании. Должна открыться карточка компании.
2. В строке связанной компании должны быть только иконка и название: без `Billing`, `billing_contact`, `CMP-...`, типа связи и английских служебных подписей.
3. В карточке компании проверить профиль, ленту и доступность редактирования для superadmin.
4. `/admin/contacts`: поиск по названию компании (например, «МДремстрой») возвращает связанный контакт; отсутствующий RPC не даёт toast schema-cache.
5. `/admin/deals`: поиск по тому же названию возвращает связанные сделки.
6. `/admin/payments`: поиск по названию компании находит платёж через заказ или связанный контакт.
7. `/admin/companies`: поиск, открытие карточки и возврат назад работают.
8. Проверить консоль и сетевые запросы; зафиксировать synced SHA, migration result, publish URL и отсутствие runtime-ошибок.

## 5. Критерий завершения

Companies считается опубликованным только после успешного применения миграции, Publish и прохождения всех пунктов smoke-test. GitHub merge, успешный build или открытый Lovable preview сами по себе не являются production acceptance.

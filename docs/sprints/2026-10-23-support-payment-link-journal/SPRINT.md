# Журнал запрошенных платёжных ссылок

Клиент просит ссылку клуба с автоплатежом. Владелец разрешил использовать
существующую функцию канонической карточки Контакта. Локальный журнал пока
не различает создание ссылки и её отправку, поэтому после прерывания нельзя
безопасно учесть эти действия отдельно.

Добавлена операция `create_payment_link` с прежними lease, SHA-256 ключом и
защитой reserved/uncertain/verified. Она независима от `reply`. Регламент
предписывает штатное создание без автоотправки, проверку результата, отдельную
отправку в изолированном саппорт-боте и сохранение границ реальных платежей.

Проверка: Python unittest покрывает неоднозначное создание после перезапуска,
уточнение результата до verified, блокировку повтора и независимую отправку.
Схема SQLite и существующие записи сохраняются. Установка — из точного merged
SHA в новый каталог runtime с побайтовой проверкой и переключением release.json;
существующий runtime не редактируется. Клиентские идентификаторы/URL не включены.

Production код, UI, платежи, продукты и права не меняются. Lovable execute,
Publish и скриншоты ПК/mobile для этого локального изменения не применимы.

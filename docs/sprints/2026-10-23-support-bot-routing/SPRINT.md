# Единый саппорт-бот и проверка доступа к эфирам

Владелец поручил переводить новые вопросы из старых служебных ботов в саппорт.
Одна операция `reply` не позволяет независимо учесть уведомление о переходе
и содержательный ответ в новом канале по исходному вопросу. Добавлена локальная
операция `redirect_support` только для source=telegram. Прежние отпечатки,
SQLite-схема, lease и запрет повтора reserved/uncertain/verified сохранены.
Уже отправленный ответ не повторяется ради смены канала.

Регламент требует точного auth user UUID в двух изолированных служебных
контекстах, проверенной публичной ссылки саппорта и ожидания «Старт», если
диалог недоступен. Перенос не снимает требование ответа, не создаёт контакт
и не затрагивает личный Telegram/Business или активную работу сотрудника.
Опрос не является рассылкой старым контактам.

Для эфиров закреплена проверка точного продукта, content_month, реальных оплат
за нужный месяц и тарифа. Отдельный вебинар и его цену можно предложить только
после проверки существующего каталога. Дополнительные материалы описываются
нейтрально, без обвинений и непроверенных сроков; внутреннее уточнение допускается
только в указанной владельцем технической группе, без ПДн клиента.

Проверка: 13 Python unittest, включая повтор после перезапуска, независимый
ответ, невозможность повторить прежний ответ и запрет redirect для других
source; diff-check. Установка — из точного merged SHA в новый каталог runtime,
с побайтовой проверкой и атомарным переключением release.json. Установленный
runtime не редактируется; действующий lease и журнал сохраняются.

Это локальный журнал и регламент, без изменения production кода, UI, данных,
платежей, функций или прав. Lovable execute/Publish и визуальные UI-проверки
для этого scope не применимы. Клиентские идентификаторы, файлы и URL исключены.

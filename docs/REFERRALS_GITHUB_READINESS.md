# Отчет о выполненной работе: готовность Referrals 1.0 в GitHub

## Реализовано

- регистрационная ссылка `/r/{partner_code}` с серверной проверкой времени захвата;
- отдельная вкладка «Партнёрство» в меню настроек: ссылка, условия, приглашённые, покупки, начисления и единый баланс в BYN;
- партнёрский код автоматически создаётся для каждого нового профиля; миграция также создаёт коды существующим активным профилям;
- вкладка администратора для рефералов, начислений и заявок на выплату;
- общие проценты вознаграждения и скидки настраиваются суперадмином;
- продукт может наследовать общие проценты, иметь собственные либо не участвовать в программе;
- приглашённому применяется настроенная скидка, если она выгоднее уже действующей скидки; скидки не складываются;
- суперадминистратор может включить правило 60/40; по умолчанию оно выключено, а старые начисления не пересчитываются;
- комиссия за каждую отдельную покупку рассчитывается по снимку правила продукта, без автоматических продлений;
- first-referrer-wins, ручная привязка существующих контактов администратором;
- идемпотентные начисления, сторно при полном/частичном возврате и ручное погашение выплат;
- feature flags с безопасным состоянием OFF и shadow mode;
- сервисная reconciliation-функция для пропущенных заказов;
- отдельный GitHub Actions workflow для SQL syntax, unit tests, ESLint и production build.

## Проверено локально

- миграция разбирается PostgreSQL AST-парсером `pglast`;
- referral unit tests: 4/4;
- targeted ESLint: без ошибок;
- production build: успешно;
- `git diff --check`: без ошибок;
- `npm ci --dry-run --ignore-scripts`: lockfile устанавливаем.

## Граница доказательств

Эти проверки подтверждают целостность GitHub-пакета, но не подтверждают применение SQL и поведение в реальной базе. Миграция, RLS, RPC, реальные платёжные сценарии и UI-приёмка должны быть выполнены в изолированном Lovable Preview до production. До этого feature flags остаются выключенными.

## Что будет перенесено после approval-gate

- amoCRM ID — в `company_external_ids` с provider `amocrm`;
- название, телефоны, email и реквизиты — в canonical company только по
  deterministic reconciliation;
- руководитель и должность — в реквизиты/заметку компании, не в `profiles`;
- комментарий оператора — в company feed как заметка с source row;
- подтверждённые контакты ЛПР — в отдельный реестр внешних персон;
- дата повторного звонка — в задачу `call` с idempotency key source batch + row;
- ответственная — только после точного разрешения пользователя «Полина
  Асманта». Если найдено 0 или больше 1 совпадения, controlled apply batch
  останавливается до любых записей, чтобы не получить компании без задач.

## Stop-guards

1. До отдельного approval-gate нет записей в `companies`, feed или tasks; preview
   хранит только входной batch и не создаёт CRM-сущности.
2. Две строки с одинаковым УНП не merge/link-ятся автоматически.
3. Невалидные/пустые УНП не используются как canonical key.
4. Руководитель не создаётся как обычный контакт.
5. Пустые поля источника не очищают существующие canonical значения.
6. Весь execution получает `source_batch_id` для отчёта и rollback только
   собственного batch.

# Шаг 5: ссылки на источники в формулировках ИИ

После исправления оценок живой needs дважды успешно отработал, включая
сохранение ручной оценки и комментария. На company два вызова отклонены
строгим валидатором: «ИИ указал неподтверждённые источники». Ручное
позиционирование и ответы сохранились. Содержимое отклонённых ответов
провайдера не сохраняется, поэтому конкретные ошибочные ссылки неизвестны.

Локальный адаптер `training-custdev/wording-sources.ts` дополняет запросы
company/positioning/usp короткими ссылками `CUSTDEV_SOURCE_N` и точной JSON
схемой массива строк. Список строится только по текущим утверждённым
потребностям разрешённых активных сегментов и текущим механизмам продукта.
Подписи редактируются прежней функцией удаления персональных данных и
ограничены 240 символами; полные исходные данные не меняются. Исходные ID
в дополнительный справочник не добавляются. Коллизии ссылок с реальными
ID исключены.

Ответ преобразуется только по карте данного запроса и затем проходит
НЕИЗМЕНЁННЫЙ канонический validateAiOutput. Неизвестные ссылки, объекты,
непроверенные потребности, чужой сегмент и устаревшие источники не становятся
допустимыми. Существующие точные канонические ID остаются совместимы с
прежним валидатором. В истории сохраняются исходные ID, не короткие ссылки.
Нет автоматического повтора ИИ, дополнительных вызовов или новых разрешений.
quotes/needs не меняются; ручные варианты и механизм предварительного
просмотра/подтверждения сохраняются.

Backend-only релиз: один managed deploy training-custdev после merge/CI и
ревизии Lovable; заголовок `bkb-step5-wording-sources-v3`. index.ts,
`_shared/**`, cb21-release, preflight-manifest, SQL, RLS, Auth, config,
уведомления, другие функции и frontend не меняются. Это проверяется
штатными attestation/preflight gates. Ранее успешно развёрнутые семь
пакетов PR685 не повторяются.

Проверки: scoped sources/schema, обратное преобразование, отсутствие
расширения whitelist, сохранность входных данных, PII-redaction,
коллизии/устаревшие источники; реальный handler→SQL→история→submit→admin
review с короткой ссылкой модели. После deploy требуется живое прохождение
company/positioning/usp и окончательная сдача/проверка только в разрешённом
тестовом аккаунте.

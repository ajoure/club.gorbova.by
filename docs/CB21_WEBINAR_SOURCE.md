# Источник «Продающий вебинар» для анкеты ЦБ21

Подтверждённый адрес (вариант с `anketa_direct` не добавляется):

```text
https://gorbova.by/predzapiscb21anketa?src=platforma&utm_source=veb&utm_medium=141026&utm_campaign=cb21_preregistration&utm_content=anketa_veb
```

В существующем редакторе блока анкеты банк содержит 11 источников. Первые
10 адресов сохранены побайтно; новый источник называется «Продающий вебинар».
Каталог общий для браузера и `site-form-submit`. Исходные метки сохраняются
для группировки статистики и в метаданных анкеты; отображение на русском
не переименовывает метки: `veb` — «Продающий вебинар», `141026` — «Вебинар
14.10.2026», `anketa_veb` — «Анкета вебинара».

Учёт переходов, анкет, контактов и новых/существующих аккаунтов использует
существующие journeys/RPC. Первое касание не переписывается при переходе
по другой ссылке. Человек, пришедший ранее по иному источнику, сохраняет
исходную атрибуцию. Никакого изменения истории или пересчёта данных нет.

## Managed применение после GitHub PASS и merge

1. Сверить точный merged SHA, дерево и отсутствие локальных правок Lovable.
2. Применить только `20261014153210_cb21_webinar_source.sql`:
   `submit_site_questionnaire` prosrc MD5 до —
   `10378f20d4b2ca9836a6e5be304e84de`, после —
   `8c5d623cb3c84fd7741ad3e893f6e593`. Миграция меняет одну запись
   каталога VALUES, допускает повтор и останавливается при иной версии.
   Владелец, SECURITY DEFINER, search_path и ACL должны совпасть до/после.
3. Развернуть только `site-form-submit` с локальным `questionnaire-source.ts`.
   Не развёртывать другие функции, не менять `_shared`/Auth/RLS/таблицы.
4. Проверить точный URL, 11 ссылок, старые 10 адресов и русские подписи
   на опубликованном интерфейсе ПК и мобильного viewport после Publish.
5. Read-back: функции визитов и статистики не изменены (prosrc MD5
   `4901f607849870785c19d8391e7c2d59` и
   `f3bf6885696fe748b39677a770b8f8ca` соответственно). Анкеты, сделки,
   доступы, уведомления, страница «Спасибо» и Telegram-ссылки не меняются.

Проверки в песочнице подтверждают сохранение точных меток в анкете,
привязку к правильному контакту, идемпотентность, прежние права функции,
остановку при drift и раздельные группы статистики `anketa_veb`/
`anketa_direct` для обоих типов аккаунтов. Production smoke не отправляет
анкету, OTP или сообщения и не создаёт пользователей/контактов/доступов.

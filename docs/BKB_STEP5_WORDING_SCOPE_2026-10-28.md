# Шаг 5: отдельная задача для каждого ИИ-варианта

На v3 company и positioning успешно прошли проверку источников, но оба
реальных ответа объединили позиционирование и УТП. Дополнительное УТП
ошибочно превращало исходные затраты времени в эффект услуги. Авторские
утверждённые тексты сохранились; спорный сегментный preview закрыт без
применения. Это противоречит отдельным формулам разделов 4/5 исходного ТЗ.

Локальный адаптер теперь явно задаёт ровно одну задачу: общее ядро компании,
адаптация для сегмента либо одно УТП выбранной карточки. Та же задача
записана в описании text схемы ответа и метаданных запроса. Отдельно
разделены исходные затраты/пожелания и достигнутый эффект; доказательство
берётся из evidence. Без него УТП остаётся гипотезой с missing_evidence.
Ответ с заголовком другого задания отклоняется с понятным сообщением;
данные сохраняются, автоматического повторного вызова нет. Это структурная
проверка, не обещание универсальной семантической проверки свободного текста;
ручной выбор формулировки и административная проверка остаются обязательными.

Только handler/local helper/два теста/этот документ. Маркер
`bkb-step5-wording-scope-v4`; index, shared, schema, RLS, config, derived
manifests и frontend не меняются. Один managed deploy training-custdev после
merge/CI и ревизии Lovable. Остальные пакеты не повторяются. После deploy
нужны реальные три ИИ-варианта, проверка сохранности ручного текста,
гипотеза без выдуманного доказательства, submit/admin review и финальный
Publish с опубликованными ПК/мобильными скриншотами.

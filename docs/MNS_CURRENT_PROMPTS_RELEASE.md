# Единый актуальный сценарий ответа МНС

## Причина

`/audits/mns-response` вызывал отдельный `mns-response-generator` с жёстко
заданной старой инструкцией: Указ №510, обязательная книга учёта проверок.
Сценарий `107NK` в `/ai` уже использовал авторский промпт и четыре готовых
вложения с Указом №227. Это два разных обработчика одной видимой функции.

Официальное подтверждение перехода с 01.01.2026:
https://nalog.gov.by/news/33009/ . Номер на предоставленном скриншоте — 510;
оснований автоматически запрещать любые ссылки на №550 нет.

## Изменение

Старый endpoint стал адаптером к `gorbova-ai-chat`: сервер ищет единственный
активный видимый `107NK`, передаёт исходный Bearer пользователя и совместимо
возвращает `responseText`, `needsClarification`, `requestType`. Права и квоты
основного обработчика действуют в обоих входах. Старый UI показывает причину
отказа, сохраняет исходный текст/изображение при уточнениях и не теряет ввод
при ошибке. История `mns_response_documents` не переписывается.

Только для `107NK`:

- авторский промпт и все вложения должны быть непустыми и готовыми; источник
  №227 должен присутствовать в названии и тексте; ошибки чтения и превышение
  лимита базы 500000 символов закрывают генерацию;
- системная инструкция передаёт текущую дату и приоритет авторских источников;
  инструкции анализа баланса и числовая эвристика качества не применяются;
- текст исходного запроса передаётся полностью до 100000 символов; больший
  документ отклоняется вместо молчаливого усечения;
- исходный текст хранится в закрытой истории разговора и восстанавливается
  только для владельца и того же сценария. Для старого успешного разговора
  без сохранённого текста предыдущий ответ помечается непроверенным резюме;
  недостающие факты нужно запросить, оригинальный файл не реконструируется;
- полный ответ проверяется до показа и сохранения. Ссылки на Указ №510
  (включая исторические) и неотрицательные утверждения о книге проверок
  отклоняются. Готовый ответ должен ссылаться на №227; авторский запрос
  недостающих данных распознаётся также без вопросительного знака. Явно обозначенный номер запроса/письма 510, сумма 510 и №550
  сами по себе не запрещены. Отказ не сохраняет AI-сообщения и не списывает
  квоту успешных сообщений; аудит содержит только код и отпечаток источников;
- служебные данные успешного ответа содержат дату, baseline и SHA-256
  авторского промпта, формата и полного набора использованных вложений.

Проверка конкретных устаревших ссылок не является универсальной юридической
экспертизой. Дальнейшие редакции законодательства нужно добавлять в авторскую
базу; текущая дата в запросе не заменяет обновление источников.

## Ревизия и выпуск

Lovable read-only ревизия завершена: `main:agent#00000013041139#ast:GYCKRCF2`;
одна консолидированная сверка Codex: `main:agent#00000013041198#ast:F3K2ZM54`.
Данные промпта и вложений не меняются. Миграции не нужны. Общий ai-access
не меняется. Проверка закона находится в gorbova-ai-chat/mns-current-law.ts:
она не изменяет область контрольной суммы опубликованного ЦБ21. Развернуть только `mns-response-generator` и `gorbova-ai-chat`.

До execute: GitHub checks PASS, точный merged SHA, свободная каноническая
очередь Lovable, отпечатки/число старых документов и авторской базы.
После deploy: не более четырёх контролируемых синтетических AI генераций,
оба входа и продолжение без повторной загрузки, проверка metadata/истории,
неавторизованный запрос 401. Никаких отправок документов клиентам/МНС.
Publish после этих PASS. Снять опубликованные ПК и мобильные результаты
обоих входов с URL, SHA, viewport, без персональных данных.

## Проверка упаковки Lovable Cloud

При первом deploy из PR603 современная функция развернулась, но Cloud
отклонил legacy: импорт из папки соседней функции не попадает в пакет.
Publish не выполнялся. Адаптер теперь не импортирует юридическую проверку:
он принимает только проверенный результат того же 107NK с серверным
`mns_response_kind`, `mns_law_validation`, `scenario_code` и `prompt_id`.
Новый юридический промпт в адаптере не создаётся.

`scripts/verify-mns-function-bundles.mjs` проверяет каждый entrypoint в
отдельной временной папке с копией только самой функции и `_shared`,
как пакует Cloud. Компиляция в полном checkout такую ошибку не обнаруживала.
Контрольная сумма ЦБ21 и его функции остаются прежними.

## Runtime: имя файла источника

Два синтетических UI-запроса после deploy отклонены до модели с
`mns_corpus_unavailable`; ответов и списания успешной квоты нет.
READ-ONLY сверка `main:agent#00000013041698#ast:DUUYH55D` установила:
все четыре вложения ready/непустые, запрос БД успешен, единственный 107NK
совпадает. Реальное имя источника
`Указ_Президента_Республики_Беларусь_от_06_06_2025_N_227_ред_от_17.docx`
не распознавалось из-за JS-границы слова и подчёркиваний.

Проверка имени заменяет подчёркивания на пробелы только для распознавания
номера. Исходное имя, текст, отпечаток, авторская база и проверка выдаваемого
ответа не меняются. Регрессия включает реальное имя, отклонение 2270/1227
и выполнение настоящего canonical handler до модели с таким именем.

# Мобильная прокрутка: исправление правила body

Статус: код и локальные проверки готовы; native runtime и Publish не подтверждены.

## Диагностика

В сообщении пользователя показан курс в библиотеке: на телефоне не удаётся прокручивать вниз, аналогично на других вкладках. Персональные данные из снимка не переносились в репозиторий.

PR #428 добавил `html, body { overscroll-behavior-y: none; }`. При этом существующее базовое правило задаёт `overflow-x: hidden` обоим элементам. Для body это также вычисляет overflow-y в auto. В DashboardLayout страницы растут по содержимому, документ прокручивается через root, а body оказывается промежуточным scroll container без собственного диапазона прокрутки. `none` на таком промежуточном контейнере может остановить жест до document root.

Это подтверждённое небезопасное сочетание CSS, согласующееся с жалобой; воспроизведение именно на устройстве клиента ещё не выполнено. Механика описана в [MDN overscroll-behavior](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overscroll-behavior) и [MDN overflow](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/overflow).

## Изменение

Единственное production-изменение: ограничить `overscroll-behavior-y: none` элементом html. Body сохраняет стандартный auto и передаёт прокрутку корню. Ограничение горизонтального переполнения, диалоги, доступы, данные и защита от JavaScript hard-reload из PR #428 не изменены.

## Проверки

- Новая CSS contract-проверка падает до патча на body none и проходит после.
- Два touch-event теста проверяют, что движение пальца вверх не отменяется PullToRefresh: с callback и без него.
- Все локальные тесты: 229 файлов / 1538 тестов PASS (Node24.19.0).
- TypeScript app, целевой ESLint, production build и diff-check PASS.
- Это не доказательство нативной прокрутки: jsdom не выполняет браузерный scroll chaining.

## Обязательная приёмка перед завершением

1. Использовать встроенный браузер и единственный канонический Lovable проекта `796a93b9-74cc-403c-8ec5-cafdb2a5beaa`. На момент проверки доступен только Chrome, создание iab возвращает `Browser is not available: iab`; сторонний браузер не использовался.
2. Прочитать текущий canonical chat и завершить plan-only ревизию публикации. Попытка отправки plan-only через Lovable connector вернула INVALID_ARGUMENT; чтение последних сообщений подтвердило отсутствие нового сообщения. План не считать принятым.
3. Не смешивать с незавершённой приёмкой PR #430: последний доступный отчёт Lovable оставляет runtime/Publish gate broadcast preview открытым. Перед общим Publish получить актуальный статус этого gate, не выполнять и не признавать чужой scope завершённым.
4. После зелёного PR проверить точный SHA и синхронизацию. Через штатный UI без impersonation, новых пользователей и изменения доступов открыть длинный доступный курс, пройти вниз и вверх. Проверить библиотеку и ещё одну длинную вкладку, открытие/закрытие бокового меню, вложенную горизонтальную прокрутку и диалог.
5. Проверить, что жест у верхнего края не вызывает reload и введённое содержимое формы не исчезает; не создавать реальную ссылку/платёж.
6. После допустимого Publish повторить smoke на опубликованном URL, записать fingerprint/asset и SHA, приложить скриншоты ПК и mobile390×844 без клиентских данных. Не выдавать суженный desktop viewport за тест на реальном iPhone.

Rollback — отдельный revert этого узкого PR через обычный workflow; он вернёт проблемное body-правило, поэтому использовать только при подтверждённой новой регрессии. Автосохранение черновиков, payment/access changes и другие CSS-перестройки вне scope.

## Подтверждённые дефекты

- `PullToRefresh` в AdminLayout и DashboardLayout использовался без `onRefresh`: жест вниз приводил к `location.reload()`. Проверка только активного поля теряла смысл после blur; собственный pointer-capture дополнительно снимал фокус. События portalled-диалога всплывают к React-родителю. Это воспроизводимый путь потери незавершённой формы, но не доказательство причины каждого исторического случая.
- `LazyErrorBoundary` автоматически перезагружал приложение при ошибке загрузки чанка. При блокировке повтора ошибочно показывал runtime-error вместо chunk-error.
- Обещание «мы увидим её в логах» было недостоверным: сохранялся только browser console, серверной доставки не было.

Lovable read-only preflight подтвердил публикацию с fingerprint `2026-09-05T07:23:36Z`, код эквивалентен базе PR. Сохранённого stack инцидента нет. Ошибки RLS/валют/данных сделок не подтверждены. Auth/query-ключи используют user.id, TOKEN_REFRESHED сам по себе не включает loading заново. Service worker не перезагружает страницы при обновлении; переход по нажатию уведомления — отдельное явное действие.

## Изменения

1. Жест refresh никогда не делает hard reload; работает только при явно переданном callback. Фокус не снимается принудительно, открытые диалоги не перехватываются. Обычная прокрутка сохранена. CSS отключает нативный overscroll-refresh в поддерживающих браузерах.
2. Error boundary никогда не обновляет страницу автоматически. Два разных русских экрана, явная кнопка обновления и предупреждение о несохранённых изменениях.
3. Копируемый диагностический код/отчёт. В нём нет raw message, текста/ID сделок, query, origin, токенов, e-mail, component stack или полного UA. Только фиксированные категории, React-код, имена assets с координатами, build, время и UUID события. При отказе Clipboard API доступно ручное копирование из textarea.
4. Только `/admin/deals` отправляет best-effort отчёт в `report-client-error`. Ожидание ограничено 5 секундами, не вызывает повторных ошибок и не блокирует экран. Остальные маршруты оставляют локальный отчёт.
5. Endpoint использует verify_jwt=true, серверный getUser и существующий deals.view. Обычный клиент не получает прав. Строгая схема, максимум4096байт. Никаких миграций, RLS или новых таблиц.
6. В существующий audit_logs пишется action `frontend.route_error`, actor_type=user, actor_user_id только из проверенной сессии. UUID строки детерминирован из actor и серверной UTC-минуты: DB PK ограничивает запись до1/минуту даже между изолятами. Повтор diagnostic.id дедуплицируется10минут. Другой отчёт в занятой минуте получает429 и **не** объявляется сохранённым. После insert обязательный read-back.

# Управляемый импорт подтверждённой истории 17/18

Прямой sandbox-канал не имеет `FOR UPDATE` на profiles. PR #448 уже применён,
но до этой операции ни одна из 286 недостающих покупок не вставлена.

Миграция добавляет два service-only RPC. Тела берутся из проверенных batch.sql
и repair-course-scope.sql; сохраняются все проверки владельца, покрытия,
каталога, окон клуба, триггеров и побочных эффектов. Дополнительно разрешены
только SHA-256 канонического JSONB 15 утверждённых партий (286 фактов) и одной
партии 7 исправлений объёма курса. Сами клиентские UUID/исходные данные в новой
миграции не хранятся. Изменённый payload отклоняется целиком.

Режимы: dry-run, rollback (подтранзакция выполняет записи и откатывает их),
execute. Каждая партия атомарна; повтор возвращает нулевое число изменений.
ACL запрещает anon/authenticated; дополнительная проверка auth.role запрещает
вызов без настоящего service_role. Права sandbox и служебные ключи не меняются.
Миграция только определяет функции, сама покупки и доступы не изменяет.

Порядок: Lovable plan-only ревизия → GitHub checks/merge → применение exact
миграции → ACL/hash/read-back → все dry-run → rollback первой партии → 15
небольших execute с read-back/replay → scope dry-run/rollback/execute/replay →
отдельный preview существующего rules-retroapply для 68 подтверждённых Business.
Другие source-конфликты, G9, Auth и рассылки этой операцией не затрагиваются.

Проверки PGlite: ACL и подмена payload, откат/повтор истории без денег/доступов,
полный откат при неожиданном access-триггере, сохранение срока при scope repair
и отказ без подтверждённого оплаченного Club — PASS.

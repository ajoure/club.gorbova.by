Для единственного неизвестного факта 17:87 владелец передал дату
`2024-05-15T12:17:17+03:00` (`09:17:17Z`). Это подтверждение владельца по ответу

это происхождение. Исходный timestamp покупки сохраняется с точностью до секунды.

Новая миграция устанавливает только `admin_confirm_historical_cb_date`.
Это service-only RPC с одной разрешённой контрольной суммой одного приватного
payload; исходный RPC на 285 дат и его разрешённые данные не расширяются.
Проверяются ID, владелец, продукт, source refs/batch, неизвестная дата, оплаченный
исторический статус, нулевые суммы и отсутствие месяца. Меняются `deal_date` и
датировочная meta; остальные поля и самостоятельные связи денег/доступов
проверяются после изменения внутри той же транзакции. Повтор не создаёт аудит.

Порядок через канонический Lovable Cloud: plan-only → exact merged SHA → managed
migration → ACL read-back → dry-run 1 → rollback (date/audit delta 0) → execute 1 →
read-back exact timestamp/provenance и прочих полей → replay 0. Приватный payload
передаётся отдельно, без ФИО, email и телефона. Не создавать SQL/код в Lovable.

Это исправление данных: frontend/Edge Functions/Publish не требуются. Проверить
дату в уже опубликованной карточке, не нажимая выдачу доступа. Результат проверок
и фактические дополнительные доступы внести в отчёт для сотрудника.

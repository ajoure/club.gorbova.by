# Две кнопки уведомления предзаписи

## Изменение

В существующем редакторе рассылок первая кнопка остаётся в
`button_text` / `button_url`. Необязательная вторая кнопка сохраняется в
`metadata.additional_button = {text, url}`. Остальная metadata сохраняется.
Те же настройки передаются в ручной, событийной, запланированной рассылке
и существующей отправке теста администратору. Каждая кнопка занимает одну
строку Telegram. `meta.reply_markup` сохраняет клавиатуру для существующего
отображения кнопок в контакт-центре. Без второй кнопки поведение прежнее;
персональная кнопка эфира остаётся единственной в своей ветке.

Событийный отправщик разрешает токены URL кнопок из опубликованной страницы
«Спасибо» через существующий resolver анкеты. Ссылки канала и Telegram
Business сохраняются побайтно, без tracking-замены. Подготовленный текст
личной переписки управляется Telegram Business и не меняется.

## Конфигурация одного существующего шаблона

Только шаблон `78e8bae2-cd0c-4eb7-a577-f872e1a4c4ab`:

```json
{
  "message_text": "Спасибо! Ваша анкета предзаписи получена ✅.",
  "button_text": "Ваш бонус",
  "button_url": "{{questionnaire.channel_url}}",
  "metadata.additional_button": {
    "text": "Получить бонус от Катерины",
    "url": "{{questionnaire.personal_chat_url}}"
  }
}
```

Изменение применяется только через Lovable Cloud после merge и PASS CI.
Не нужны миграции, новые таблицы, RPC, триггеры или правила доступа.

## Порядок и проверки

1. Сверить точный merged SHA и единственный scope. Развернуть
   `telegram-mass-broadcast`, `telegram-send-test`, затем
   `process-scheduled-broadcasts`, включая изменённые локальные/_shared
   зависимости. Publish проверенного редактора.
2. Read-only preflight: шаблон одобрен, очередь pending/processing = 0;
   сохранить прежние значения трёх полей и metadata для rollback.
   Сверить сохранённое условие/cutoff/primary bot и MD5 ссылок из Thanks:
   канал `927be7d6c2a1db0a1536943cf90c3065`,
   Business `84728b2e646eeead81f8fe2bdb4d29d5`.
3. Условно обновить только одну строку, сохранив все остальные поля и
   ключи metadata. При дрейфе состояния/неожиданном rowcount остановиться.
4. Read-back: изменён ровно один шаблон; остальные поля, URLs, событие,
   cutoff и уникальный ключ доставок прежние. Старые сообщения/журнал не
   переписывать и повторно не отправлять. Новые естественные события
   обрабатываются обычным диспетчером.
5. Без отправки проверить реальный payload resolver/keyboard: короткий
   текст без URLs/Markdown/пояснений, две строки с точными URL.
   Обычные `dry_run` отправщиков не вызывать как гарантию отсутствия
   отправки: этот флаг сам по себе не заменяет проверку побочных эффектов.
6. По опубликованному admin URL проверить повторное открытие настроек и
   предпросмотр на ПК и мобильном viewport, сохранить безопасные скриншоты.

Реальная тестовая отправка требует разрешения пользователя. Без неё
различать проверенный payload/конфигурацию и фактическую отправку Telegram.

Rollback: восстановить сохранённые поля и metadata ровно одного шаблона;
при необходимости развернуть предыдущие версии этих трёх функций/редактора.
Журнал доставок, анкеты, контакты, Auth, покупки, доступы, страницы «Спасибо»
и подготовленный Business-текст не изменять.

# Длинная запись ЦБ: ограниченное распознавание

Статус: реализация для managed Lovable, production dry-run и распознавание ещё не выполнялись.

Практическое занятие длится около 208 минут и не имеет русских субтитров. Обычный скрипт ограничен 30 минутами и остаётся без изменений. Новый `transcribe-long-course.mjs` использует существующие таблицы и RPC: источник/задание до 6 часов, части по 90 секунд, одна попытка на часть. Миграции и развёртывание Edge Functions не нужны.

Перед запуском явно выбираются существующие активные видеоблоки курса. Выключенные исторические разделы не включаются и не получают новые привязки. Наличие русских субтитров, изменение видео, ревизии или выбранного урока останавливает работу.

Dry-run последовательно скачивает диапазоны HLS и декодирует по одной части. В памяти нет полной записи или полного PCM: сохраняются только метаданные плейлиста и хеши, медиа ограничены существующими лимитами range/decode. Манифест не содержит ссылок провайдера, ключей или текста. 208 минут дают 139 частей; точное число берётся из проверенной длительности провайдера.

Запуск только внутри канонической managed-среды Lovable:

```sh
node scripts/sales-knowledge/transcribe-long-course.mjs --managed-lovable \
  --mode dry-run --alias VIDEO_ALIAS --block-ids ACTIVE_BLOCK_ID_1,ACTIVE_BLOCK_ID_2 \
  --report /tmp/long-course-manifest.json
```

После ревизии манифеста и точного SHA256 выполняется не больше 20 выбранных частей за один вызов:

```sh
node scripts/sales-knowledge/transcribe-long-course.mjs --managed-lovable \
  --mode execute --manifest /tmp/long-course-manifest.json \
  --approved-manifest-sha256 REVIEWED_SHA256 --parts 0,1,2 \
  --report /tmp/long-course-batch-1.json
```

Каждый файл отчёта создаётся с `wx` и правами 0600. При возобновлении готовые части сверяются с манифестом и не отправляются повторно на платное распознавание. Неясный результат, незавершённый захват или сбой после захвата удерживает часть; автоматического повторного запроса нет. Финализация разрешена только после всех частей с точными границами и хешами. Полученная расшифровка — `paid_private`, `unreviewed`; скрипт не публикует её клиентам и не добавляет автоматически в базу продавца.

Локальная проверка: 36 тестов нового режима, прежнего STT и импорта проверенных субтитров. Есть сценарии 139 последовательных частей без записи/оплаты, пакетного продолжения, повторного запуска готовых частей, неясного ответа, сбоя после захвата, изменения аудио/ревизии, закрытой привязки, лимита пакета и неполной финализации. Реальные сеть, декодирование и стоимость Lovable требуют отдельного managed dry-run; локальные тесты их не подтверждают.

Конференции №4/5 не входят в этот режим: у них есть субтитры с проблемами качества. Нельзя обходить их проверку запуском полного STT или менять доступность разделов ученикам ради импорта.

Dry-run отмечает окна цифровой тишины (все PCM-сэмплы равны нулю). Выбранные для исполнения такие окна останавливаются до записи и оплаты; автоматической подмены пустого аудио выдуманным текстом нет. Остальные шумы, музыку и отсутствие речи этот признак не классифицирует.

### Границы AAC (25.09.2026)

Первый managed dry-run остановился без записей и STT: окно90–180с
декодировалось в89936мс. У Kinescope AAC32кГц edit list пропускает2048
сэмплов, а последние64мс номинального сегмента находятся в следующем.
Для длинного STT диапазон включает один следующий реальный сегмент,
если он существует; `atrim` и проверка точной длительности остаются.
Последнее окно не продлевается и не дополняется тишиной.
Обычные gap-аудиты сохраняют прежний выбор диапазонов и хеши.

Регрессионный тест `long-audio-boundaries.test.mjs` требует ffmpeg:
создаёт AAC32кГц fMP4/HLS с edit list2048, воспроизводит отказ старого
диапазона, проверяет начало/середину/неполный хвост и сравнивает PCM
с полной декодированной синтетической записью по исходному таймлайну.
Это локальное доказательство; полный managed dry-run остаётся обязательным.

### Несколько файлов одной HLS-дорожки

Следующий managed dry-run выявил два окна (54/108), пересекающих смену
файла одной дорожки. Отдельная read-only проверка реальных фрагментов:
оба PCM по2880000байт, AAC32кГц, шаг PTS0,032с без сбросов и разрывов.
Длинный захват теперь группирует сегменты по файлам, загружает диапазоны
последовательно и декодирует общий init+диапазоны в порядке плейлиста.
Переход разрешён только на новый файл с offset0 при непрерывном времени;
внутри файла байты обязаны идти вплотную. Общий лимит10MB, до16 диапазонов.
Старый gapRange и старые манифесты не меняются.
Регрессионная синтетическая запись разделена на три файла: оба стыка
сравниваются с PCM целой записи. Новый production dry-run обязателен.

Тот же multi-file захват используется для явно выбранных аудитов пропусков
PR569. Обычный путь без выбора остаётся прежним. Регрессия дополнительно
проверяет130-секундный пропуск через два стыка и обе его части.

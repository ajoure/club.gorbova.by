# Нейросеть: исправление диагностики генерации

Состояние: код подготовлен в отдельной ветке `codex/neural-error-contracts`
от `760cc45723c9025e59f4efa5efacd2864cfa2da1`. Production не изменён.
Аудит всех обнаруженных проблем находится в отдельном PR #444.

## Изменения этого спринта

- **F01:** внешняя анкета, legacy/corporate/package генерация и выдача ссылок
  читают тело `FunctionsHttpError.context`, сохраняя исходный Response.
  Пользователю выводятся русские сообщения по списку допустимых кодов.
  Неизвестные сообщения, URL и подробности провайдера не копируются в новый
  публичный текст ошибки. Существующий общий reader переиспользован;
  поведение нормализатора других модулей не изменено.
- **F02:** HTTP 200 сам по себе больше не означает успех внешней генерации.
  Нужны `success: true`, допустимый статус и UUID готовых документов.
  При `failed/blocked`, пустом результате или неизвестном исходе
  `generated_at = NULL`, сохраняется безопасный код причины.
  Частичность сохраняется в `error_code` и `metadata`, без нового CHECK-статуса.
  Sender вызывается только после подтверждённой записи submission.
  Документы из строк результата со статусом ошибки не отправляются.
- **F04:** ошибка чтения списка анкет отличается от успешного пустого списка;
  кнопка повторяет только чтение.
- **F05:** знаменатель количества документов берётся из `total_documents`,
  затем из совместимых старых полей. Число позиций шаблона не подменяет число
  документов, созданных для нескольких исполнителей.
- **F14:** журнал пакетного генератора выводит числовые счётчики ошибок и
  блокировок; сырой список ошибок и идентификаторы удалены из этого сообщения.

Внешняя анкета различает частичную генерацию и подтверждение отправки.
После неопределённого результата submit повтор в текущей открытой форме
заблокирован. Это **не серверная идемпотентность**: F03 остаётся открытым,
обновление страницы и другой клиент этой защитой не покрыты.

## Ревизия Lovable

Канонический проект: `796a93b9-74cc-403c-8ec5-cafdb2a5beaa`.
Plan-only ответ: `aimsg_01m2bvdtcnena97zs81q06sz8z`, 12.09.2026 UTC.
Очередь проверена до запроса; предыдущая задача остановлена её владельцем.
Никаких code/database/deploy/Publish действий ревизия не разрешала.

Консолидированное решение Codex по плану:

- Сохранить существующие семейства `error_code`; `stage` хранить отдельно.
  Формат `<stage>.<reason>` не нужен для совместимого исправления.
- Переиспользовать Response-reader, но применить отдельную политику
  допустимых сообщений документов: общий normalizer допускает сырой fallback.
- В счётчике документов приоритет у `total_documents`, а не `total_items`.
- Не обещать пользователю «мы уже видим ошибку в журнале»: запись могла
  не сохраниться. Для неизвестного исхода требуется проверка статуса.
- Исторические ошибочные строки не исправлять этой задачей.

## Проверки и границы

44 целевых offline-теста: чтение context/clone, неизвестный HTML/SQL/payload,
HTTP 200 с ошибкой, partial, недопустимые ID, неуспех записи, сетевой обрыв,
отсутствие автоматического retry, состояние формы и повторное чтение,
совместимость счётчиков. Проверены сборка production и ссылки Edge Functions
(365 исходников, 225 ссылок). Локально прошли все 1733 теста в 258 файлах и TypeScript. Общая проверка CI выполняется в PR.

Политики Auth/JWT/RLS, миграции, шаблоны, квоты, нумерация и реальные отправки
не менялись. F03/F06–F13 и runtime-вопросы S01/S02 из PR #444 не закрыты этим
спринтом. Причина конкретного августовского обращения остаётся UNKNOWN.
Изменение диагностического кода не доказывает исправление причины генерации.

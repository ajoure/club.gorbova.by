# Контакт-центр: устойчивость редактора и аудит функций, 21.09.2026

Статус: исправления в отдельной ветке; опубликованный UI и production runtime пока не приняты. База: `d169659bc10c686869a56f8e7a21ae65c48aa94f`. Платежи исключены по прямому указанию пользователя. Production-данные, интеграции, migrations и Edge Functions не изменяются.

## Подтверждённые ошибки и исправления

1. **Конфликт с прокруткой iOS при клавиатуре.** `installAppViewport` записывал `document.scrollingElement.scrollTop = 0` внутри обработки `visualViewport.scroll`. Браузер мог снова прокрутить документ к курсору. Принудительная прокрутка удалена; оболочка приложения больше не сдвигается в обычном потоке вслед за offsetTop. Высота и координаты портальных окон обновляются только при изменении округлённых значений. Pinch zoom остаётся доступен. Сброс scrollTop появился в `5bddc7a093712e7b66cf85ab87aaca4a50b45c50`, **17 сентября 2026, 08:10:57 UTC**. Это дата изменения исходников, не доказанное время первого production-инцидента.
2. **«Без имени / Telegram не привязан» и потеря редактора.** Ключ запроса профилей зависел от порядка всей очереди. Новое сообщение меняло порядок/набор идентификаторов; во время нового запроса данные профиля исчезали. Ошибки отдельных batches проглатывались и превращались в успешный пустой/частичный результат. Идентификаторы теперь сортируются; предыдущие успешно прочитанные профили сохраняются на время загрузки/ошибки, ошибки отображаются, неподтверждённая связь не трактуется как отсутствующая. Успешный пустой результат остаётся авторитетным.
3. **Закрытие выбранного чата при изменении очереди.** Выбранная строка была привязана только к текущей странице списка. Открытая переписка теперь сохраняется при уходе строки за пределы страницы/поиска. Ручной выбор другого контакта, «Назад» и смена оператора учитываются. При перегруппировке контакта сохраняется выбранный источник, в том числе в первый кадр.
4. **Ошибка фоновой проверки ботов удаляла редактор.** `isError` заставлял заменить весь чат заглушкой даже при наличии ранее загруженных каналов. Теперь остаются история, редактор и черновик, показывается ошибка с повторной проверкой; отправка блокируется до восстановления проверки доступности каналов.
5. **Черновики Telegram пропадали при remount/reload.** Текст сохраняется в sessionStorage текущей вкладки с отдельным ключом для оператора, контакта и отправителя. При восстановлении принимаются записи не старше 24 часов; очистка текста удаляет запись. Ошибки browser storage не блокируют ввод. Файлы остаются только в памяти: после полной перезагрузки вложение нужно выбрать снова. Текст не отправляется на сервер автоматически.
6. **Состояние редактора могло перейти к другому контакту.** Диспетчер чатов получил стабильный React key по исходному диалогу: переключение Instagram/тикета не переносит текст и вложение прежнего получателя. Telegram сохраняет свой отдельный черновик.
7. **Пропуск уведомлений Instagram.** Подписка слушала `direction=eq.incoming`, хотя входящие записи ManyChat и история Instagram используют `inbound`. Фильтр исправлен; Telegram по-прежнему использует `incoming`. Недоступность AudioContext при первом касании не вызывает исключение интерфейса.
8. **После фонового режима могли оставаться пропущенные сообщения.** Очереди догружаются при возвращении видимой вкладки/PWA и восстановлении сети, с общей задержкой объединения 300 мс. Открытый Telegram-чат догружается через существующий debounce после возврата и после восстановления ранее оборванной Realtime-подписки. Страница не перезагружается.
9. **Повторная отправка сообщения техподдержки по Enter.** Обработчик не проверял выполняющуюся отправку/загрузку, хотя кнопка была disabled. Добавлена синхронная блокировка повторного запроса, защита IME-ввода, сохранение текста/файла при ошибке и явная повторная отправка. Поле не редактируется во время отправки.
10. **Карточка контакта игнорировала доступную высоту.** Старые `!important` размеры от `100dvh` перекрывали ограничение visualViewport. Для мобильной карточки контакта высота ограничена доступной областью, ширина учитывает боковые безопасные зоны. Визуальный результат требует браузерной приёмки; физический iPhone ещё не проверен.

Нельзя трактовать зелёные локальные тесты как доказательство полной исправности всех интеграций, восстановления ранее не принятых сообщений или визуальной приёмки iOS.

## Регрессионные доказательства

Новые тесты запущены также на исходном `d169659bc` с временной подстановкой старых четырёх исходников и гарантированным восстановлением рабочих файлов. Получено **4 ожидаемых FAIL**:

- `appViewport.test.ts`: старый код сбрасывает Safari scrollTop;
- `useUnifiedInbox.identity.test.tsx`: теряется numeric Telegram ID при расширении очереди;
- `TelegramChannelSeparation.test.tsx`: ошибка проверки отправителей удаляет редактор;
- `useIncomingMessageAlert.test.tsx`: канонический inbound Instagram не вызывает уведомление.

После исправлений все четыре проходят. Дополнительно проверены изоляция/восстановление/очистка текстовых черновиков, отказ storage, смена оператора, Back/выбор чата, фоновые обновления и синхронная блокировка повторной отправки тикета. Все отправки в тестах замоканы.

Локальная финальная проверка: **286 файлов / 1 863 теста PASS**, production build PASS, `tsc -p tsconfig.app.json --noEmit` PASS, Edge Function contracts PASS (365 sources / 225 literal references), lint новых hooks и viewport PASS, `git diff --check` PASS. Сборка предупреждает о крупных chunks; это не runtime-приёмка мобильного устройства.

## Незавершённые внешние проверки

- Connector Lovable читает проект и историю, но `send_message` отклонён: подключение не имеет `projects:write`. Задание plan-only фактически **не отправлено**.
- Последний доступный read-back проекта: main `d169659bc`, `ready`, `is_published=true`; предыдущая tagged-test cleanup задача завершена. Это не доказательство публикации этого патча.
- Встроенный браузер недоступен; попытка открыть production через Chrome остановлена сообщением об открытом UI другого расширения. Каноническая вкладка Lovable также закреплена за другим браузерным сеансом; дубликат не создан, чужое состояние не изменено.
- До восстановления браузерного доступа/канонического Lovable: не merge/Publish; не объявлять production-аудит и визуальную приёмку завершёнными.

Некритичные пункты для следующей read-only ревизии: EmailInboxView не показывает отдельное состояние ошибки первичной загрузки; media-pipeline-stats считает загруженные строки jobs на клиенте и требует сверки с фактическим объёмом/лимитом выдачи. Они не являются доказанными причинами сброса редактора; широкая приёмка этих функций остаётся открытой.

## Следующий шаг и откат

После доступа выполнить одну консолидированную read-only plan ревизию Lovable: текущая очередь/owner, точный SHA, ошибки route/profile/channel RPC, агрегаты входящих и уведомлений каждого транспорта. Без SQL-writes, deploy, сообщений клиентам и тестовых пользователей. После PASS проверить preview, merge точного PR, синхронизировать merged SHA, Publish и получить desktop/mobile evidence без персональных данных. Проверить ввод, переключение отправителя/контакта, background/resume, открытие/закрытие карточки и сохранение текста. Отдельно подтвердить клавиатуру на физическом iPhone/PWA.

Откат: revert только коммита данного PR с обычными проверками/публикацией. Миграций и изменений production-данных нет; sessionStorage-черновики не отправляются автоматически.

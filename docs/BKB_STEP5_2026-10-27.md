## Контракт

Пять аккордеонов, семь групп, максимум десять активных вопросов на группу.
Исторический снимок вопроса сохраняется у ответа. Архивация сегмента или
респондента не удаляет интервью. Импорт по стабильным исходным ID, только
из своего портфеля, с явным выбором сегмента и защитой от дублей.

AI-действия — отдельные: цитаты, группировка/оценки, формулировка. Сервер
проверяет источники и точную подстроку цитаты, границы сегмента, диапазоны
оценок и реальные продуктовые ссылки. Частота k/N вычисляется программой
по уникальным интервью, не по количеству цитат. Ручная поправка хранится
отдельно от вычисленного балла. Нет данных о продукте — нет оценки fit.

Результат AI сначала показывается как новая версия. Применение требует
выбора «сохранить мои правки» либо подтверждённой замены. Чужой пользователь
не читает документ. У ученика нет права выставить администраторскую проверку.
Автосохранение использует revision/CAS: конфликт вкладок не затирает данные.
Ошибка AI не меняет рабочий документ. Изменение источников делает анализ
устаревшим, сохраняя историю.

## Проверки и production-граница

Unit/contract: лимиты, типы, группы, снимки, точность цитат, k/N, источники,
повторный анализ, ручные правки, недостающие данные и минимум завершения.
SQL fixture: owner/admin/чужой пользователь, запрет клиентской записи в
серверные поля, CAS, неизменяемые AI-версии, атомарные лимиты.
UI: существующий lesson renderer, admin progress, восстановление, мобильный
viewport, экспорт. Затем GitHub checks и один PR.

Production — Lovable Cloud: plan-only ревизия, только проверенный merged SHA,
перечисленные миграции/functions, read-back, безопасный runtime и Publish.
Публикация подтверждается отдельными screenshot ПК и mobile по боевому URL.
Незавершённая чужая платёжная задача в Lovable не включается в этот релиз.

## Развёртывание и приёмка

1. После GitHub checks и plan-only ревизии синхронизировать точный merged SHA.
2. Managed migration `20261027175329_bkb_custdev_workshop.sql` создаёт только
   три закрытых таблицы задания, ограниченные RPC и триггер неизменяемости
   завершённых AI-результатов; расширяет существующий CHECK типов блоков.
3. Развернуть только `training-custdev`. JWT проверяется внутри обработчика
   через Auth getUser; verify_jwt=false не означает анонимного доступа.
   Защитные лимиты: 5 AI-запусков в минуту, 100 за UTC-день на участника,
   80 000 символов входа, 12 000 выходных токенов. Никаких списаний с баланса
   ученика. Результаты и снимки сдач отделены от витрины прогресса.
4. Через существующий редактор добавить один блок «Шаг 5: Кастдев и УТП»
   после видео существующего Шага 5. Не создавать новый продукт или доступ.
   Пустые настройки источников используют предыдущие уроки того же модуля;
   при необходимости выбрать явные ID источников в редакторе.
5. Пройти сценарий владельца тестового аккаунта и отдельного ученика:
   сохранить/перезагрузить, импорт, уточнение, два AI-вызова, просмотр diff,
   ручная правка/повторный анализ, сдача, проверка admin, попытка чужого чтения.
   Без писем/платежей/новых доступов реальным клиентам.
6. После read-back и runtime PASS — Publish и отдельные снимки боевого урока
   на ПК и телефоне с URL/SHA/viewport. Локальные картинки — только проверка
   вёрстки на вымышленных данных; это не подтверждение production.

Откат интерфейса — убрать только новый блок редактором/вернуть код релиза.
Сохранённые документы, исходные ответы и историю не удалять. Миграцию с
данными не откатывать DROP-операцией. Ошибка AI оставляет рабочий ответ.

## Проверка прав в рабочем окружении

Managed read-back выявил платформенные default privileges: служебная роль
получает ALL при создании таблиц. Узкий GRANT добавляет права, но не снимает
этот исходный набор. Применённый файл миграции не переписывается.
Аддитивная миграция `20261027203832_bkb_custdev_service_acl.sql` сначала
снимает служебные права трёх таблиц и выдаёт точный набор: CRUD рабочего
документа, SELECT/INSERT AI-прогонов с UPDATE только четырёх полей завершения,
SELECT/INSERT неизменяемых версий. Права ученика, администратора и RLS
не меняются; данные и настройки default privileges не затрагиваются.

SQL fixture воспроизводит реальные default privileges и проверяет до/после,
повторное применение без потери данных, завершение AI и проверку admin.
Исходные SQL-файлы применяются дословно официальным managed `supabase--run_sql`
в Lovable Cloud. Он сохраняет явную транзакцию и не генерирует новые Git-файлы.
Drizzle ledger этим инструментом не ведётся: происхождение применения
фиксируется точным GitHub SHA, хешем SQL, официальным receipt и read-back.
В журнал Drizzle вручную ничего не добавляется.

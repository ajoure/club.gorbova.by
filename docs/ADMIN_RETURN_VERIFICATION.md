# Безопасный возврат из режима клиента

Возврат больше не выбирает цель logout из меняющейся общей сессии SDK.
Текущий JWT один раз захватывается из фактической сессии, проверяется через
`getUser(exactJwt)` и сопоставляется с исходной проверенной временной сессией.
Затем публичный `auth.admin.signOut(exactJwt, 'local')` отзывает именно её.
Обновление токена той же сессии допускается по проверенным issuer/sub/session_id;
другая сессия того же пользователя не считается исходной.

Все действующие точки изменения сессии явно используют общий facade.
На поддерживаемом браузере Web Lock удерживается с dispatch до фактического
settle, включая операции, начатые до появления return fence. Owned-вызовы
передают проверяемый lease, не глобальный флаг; после завершения lease
недействителен. Вне fence методы/параметры обычного auth сохраняются; на
поддерживаемом браузере одновременный второй ingress получает занятость
без dispatch, а не выполняется параллельно. Браузеры без Web Locks сохраняют
baseline обычного auth вне fence. Автоматический start/return там закрыт.

Переход живёт выше Routes. AuthContext сообщает фактическую сессию, а защищённое
содержимое не монтируется до проверки оператора и свежих полных canonical
прав. Неопределённые права — recovery, не успешный возврат. Подтверждённый
оператор с отозванным доступом к прежнему разделу получает штатный fallback;
дополнительного logout нет. Старый token-only backup не восстанавливается
по догадке. Исходные 15 минут не продлеваются URL-активацией или remount.

Deadline ограничивает видимое ожидание, но не отменяет SDK promise и не
освобождает занятую операцию. Новый документ должен заново получить тот же
origin lock: перезагрузка одной вкладки не уничтожает SDK другой. Ручной
вход возможен лишь после этого; текущие SDK storage/context и проверенная
сессия после ввода учётных данных сопоставляются до снятия fence.

## Проверки

`src/lib/adminReturn.sdk.test.ts`, `authMutationFacade.sdk.test.ts` и
`impersonationStorage.integration.test.ts` используют настоящий pinned SDK
2.110.7 с синтетическими пользователями, изолированным storage и закрытым
fetch. Проверяются точная цель revoke, HTTP-ошибки публичного API, refresh
rotation, истёкшие/неполные результаты, already-in-flight ingress, активный/
поддельный/истёкший lease, поздняя запись SDK и его init/auto-refresh commit
guard. Никаких настоящих logout или обращений к внешнему Auth.

`src/contexts/AdminReturnContext.integration.test.tsx` использует настоящие
AuthProvider, coordinator, ProtectedRoute/AdminRouteGuard и Auth page.
Проверяются устаревший cached admin grant с последующим fresh deny,
делегированный сотрудник, неполные права, отсутствие защищённых детей во
время fence, URL/remount/legacy, init timers, обычный auth и ручной вход с
междувкладочным изменением storage до доставки события.

`scripts/verify-auth-mutation-ingress.mjs` проверяет runtime TypeScript AST;
он включён в обычный CI unit suite через `authMutationInventory.test.ts`.
Корпус включает direct/computed/detached/destructured/namespace/dynamic-import
обходы и соседство с разрешёнными readonly namespaces. Gate не является
доказательством отсутствия произвольного обфусцированного JavaScript и не
заменяет поведенческие SDK/platform тесты.

Отдельный локальный headless platform proof использует два same-origin
документа в одном изолированном BrowserContext: реальные Web Locks,
localStorage/BroadcastChannel, уничтожение owner document при reload и
старую вкладку с raw SDK. Подробные результаты, source hashes и сведения об
очистке технического профиля хранятся в приватных артефактах координатора.
Это синтетическая проверка, не опубликованный интерфейс и не клиентский smoke.

## Границы

Facade не может остановить JavaScript старых открытых документов или отменить
внутренний SDK refresh. Точный captured revoke сохраняет цель даже при их
записях; наблюдаемый drift оставляет recovery без ложного успеха. Отсутствие
любых будущих late writes не обещается. Подтверждение revoke не означает
немедленного отзыва уже выданного access JWT.

Изменения не затрагивают SQL, RLS, роли, Auth settings, серверные действия
impersonation-start, деньги, клиентские отправки или preview storage broker.
Merge/build не означают Publish. Проверка опубликованного интерфейса на ПК
и мобильном, а также приёмка на выделенных тестовых аккаунтах выполняются
отдельным разрешённым этапом координатора.

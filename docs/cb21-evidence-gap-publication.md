# Сохранение расшифровки из проверенных пропусков

Новый путь `course_gap_publish_evidence` применим только к course-аудиту
со статусом evidence, без continuation:1–7 частей, все evidence, по одной
попытке. Старый `course_gap_publish_reviewed` для семи частей не изменён.
Новых таблиц и продуктовых правил нет.

Managed CLI `publish-evidence-gaps.mjs` принимает исходный манифест аудита
и private0600 review-file с решениями speech/non_speech, ссылками на хеши
аудио/текста, reviewer_id и примечанием. Dry-run заново читает видео,
выбранные уроки и связи, проверяет ревизию/активность/исходный VTT, собирает
текст и формирует отдельный манифест публикации. Execute требует точного
SHA256 файла этого манифеста и повторяет подготовку перед RPC.

Два хеша не смешиваются:
- capture hash — SHA256 канонического JSON исходного аудита, уже записанный
  в audit.manifest_sha256;
- review hash — SHA256 одобренного файла dry-run публикации.

RPC проверяет capture hash непосредственно по переданному тексту JSON;
provenance нормализации берётся из этого зафиксированного манифеста.
Сверяются исходный VTT, видео/ревизия/длительность, хеши/границы каждой части,
выбранные связи, схема решений и метаданные. JS повторяет bounded stable
cue ordering и сверяет весь provenance; исходный VTT остаётся без изменений.

Функция SECURITY INVOKER с пустым search_path, доступна только service_role.
Она блокирует аудит, источник и части; не меняет доступы, уроки, покупки,
бота или активность кампании. Результат остаётся paid_private/unreviewed.
Повторный вызов обязан совпадать по тексту, решениям, метаданным и provenance;
проверяются read-back и reused=true. STT этот путь не вызывает.

Проверки: PGlite выполняет реальные миграции и RPC; отдельные тесты проверяют
browser-role denial, подмену provenance/capture, неполные/удержанные части,
изменённые связи, continuation, повторный вызов и прежний семичастный путь.
Managed применение миграции, dry-run и сохранение конкретных конференций
выполняются отдельно после GitHub checks и ревизии Lovable.

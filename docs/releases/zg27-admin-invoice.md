# ZG27: административный счёт и проверка категории покупателя

Административный счёт проверяет право целевого покупателя и полную цену
первого/повторного участия до номера заказа, pending claim, документа и отправки.
Только этот доверенный handler допускает `invoice / bank_transfer / 1`.
Публичные checkout-маршруты не получают такого разрешения из запроса.
Период документа замораживается отдельно от иных продуктов:
`service_period_from=null`, `service_period_to=2027-04-30`;
доступ заканчивается в `2027-04-30T21:00:00.000Z`.

## Состав managed release

После независимой проверки и exact-head GitHub checks синхронизировать точный
merged SHA через официальный Lovable Cloud и развернуть:

- `admin-invoice-checkout-issue` — проверка категории, цены и сохранение периода;
- `canonical-document-generate-strict` — использует изменённый
  `_shared/document-data-snapshot.ts` при построении данных документа.

Миграций в кодовом изменении нет. Включение конкретного invoice offer — отдельная
проверенная конфигурационная операция, с dry-run, ожидаемым количеством строк и
read-back. Реальный клиентский счёт/отправку не использовать для smoke-теста.

## Source attestation и опубликованные пакеты

`CB21_RELEASE_DIGEST` пересчитан по неизменённому алгоритму CI, который включает
весь `_shared`. Это fingerprint кандидата исходников, а не сетевое доказательство
deployment. Исторические артефакты приёмки и проверяющие тесты не изменены.

Проверка транзитивных относительных imports от `index.ts` показала, что
`sales-runtime-worker`, `sales-runtime-control`, `telegram-webhook`,
`telegram-media-worker` и `instagram-monitor` не используют изменённые
`zg27-checkout-guard.ts` и `document-data-snapshot.ts`. Как в релизе
`docs/sprints/2026-10-29-installment-ledger-lineage/RELEASE.md`, эти пять
опубликованных пакетов и прежние взаимно согласованные health-маркеры в данном
выпуске сохраняются. Новый source digest не объявлять их опубликованной
аттестацией; не менять runtime configuration, очереди или отправки.

`preflight-manifest.generated.ts` регенерирован штатным
`scripts/health-preflight-manifest.mjs`: изменился только source hash,
allowlist из 322 функций не изменился. `system-health-full-check` в этом
выпуске не развёртывать: его OPTIONS-контракты и поведение не менялись.

## Проверка результата

Локальные реальные handler-тесты подтверждают отказ до side effects для
неподходящей категории, неверной цены и публичных попыток использовать invoice.
Документный snapshot проверяется с фиксированным сроком и без унаследованного
месяца/даты начала. Pending claim сохраняет прежнюю идемпотентность.

Локальные PASS не заменяют managed read-back, проверку сгенерированного документа
и фактической разрешённой доставки. До этих проверок счёт и выпуск не считать
исполненными.

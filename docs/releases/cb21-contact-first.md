# ЦБ21: контакты до вопросов анкеты

База: `8db7f97d967be06751e116b1b2f9bed946f419b7`.

## Изменение

В существующем редакторе формы появился `contact_first`. Он действует только вместе с `auth_mode` и `questionnaire_first`. Для остальных форм прежний путь сохранён.

Путь: контактные поля → код из письма для посетителя без подтверждённой сессии → раннее сохранение контакта → проверка/подключение основного support-бота → вопросы → существующее атомарное сохранение анкеты и переход на «Спасибо». При подтверждённой сессии подставляется только собственная карточка, повторный код не нужен. Существующая проверенная привязка бота пропускает повторное подключение. Ручной ник Telegram удаляется только из конфигурации формы ЦБ21.

Функции регистрации, входа, выдачи/проверки OTP, восстановления пароля, Telegram webhook и выдачи доступов не изменяются. Для первого входа нового аккаунта остаётся существующее «Забыли пароль?» на странице входа. Пароли существующих клиентов сохраняются.

Ранний контакт сохраняется без сделки, заполненной анкеты и учебного доступа. Недостающие поля профиля заполняются, существующие значения не перезаписываются. Подтверждение и согласие идемпотентны на контакт/страницу/форму; существующий механизм незавершённых анкет сохраняет первый срок и не дублирует напоминания. В статистике «Контакты» учитывается раннее сохранение; «Анкеты» увеличивается только после ответов. Совместимый черновик после удаления одного ручного поля Telegram переносится без потери ответов и источника.

## Проверки

Локальные Vitest включают стандартный InlineAuthForm, InlineEmailOtpForm, useInlineEmailOtp, OTP/recovery contracts и новый путь анкеты. SQL sandbox проверяет сохранение контакта без Telegram/анкеты, повтор, завершение той же анкеты, отсутствие доступа, права и отказы, UTM-статистику и guarded enablement. Deno check и production build обязательны. Без реального production OTP нельзя утверждать повторную доставку письма новому пользователю: это граница проверки, её не заменяет HTTP 200.

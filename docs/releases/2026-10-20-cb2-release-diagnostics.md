# Завершение проверки релиза ЦБ2

Продолжение PR635. База после managed migration восстановлена; код и история
исправленного заказа проверены. Все 66 покупателей сохраняют доступ, у 47
непокупателей бонуса нет, расхождений с окном клуба нет. Для проверки SMTP
authorization нужен реальный сервисный ключ среды, которого нет у SQL query
оператора. Извлекать ключ из среды или ослаблять аутентификацию не требуется.

Используется уже существующее superadmin-only действие `release_health`
функции `instagram-monitor`. Его фиксированный список запросов дополнен двумя
POST `send-email` с единственным телом `{action:"diagnose"}`: текущий сотрудник
и точный сервисный apikey среды. В ответе только HTTP-код и совпадение версии,
типа авторизации и `sent:false`. Ни SMTP, ни очередей, ни контактов, ни моделей.
Секреты остаются в runtime; URL/метод/тело не выбираются пользователем.
Для media health сохраняются и прежний JWT gateway, и внутренний worker token.

В существующей админке «Состояние системы» → «Техинфо» добавлена кнопка
«Проверить без отправки», только для суперадминистратора. Нет автозапуска.
Зелёный результат требует все шесть уникальных успешных проб.

Managed deploy после CI/merge: только `instagram-monitor` по точному merged
SHA, без миграций, изменения Auth/gateway или бизнес-логики четырёх целевых
функций. Общий CB21 digest не меняется: правки вне fingerprinted folders.
Другие функции уже развёрнуты по PR635. Не повторять repair и не запускать
production cron. Единственное разрешённое письмо уже отправлено сотрудником:
SMTP accepted, одна запись отправки и ноль новых рассылок. Не повторять отправку.

До Publish обязательны PASS GitHub checks, exact-source managed deploy/read-back,
проверки когорт и отказа без прав, реальный SMTP smoke выше и существующее
read-only действие status на опубликованной admin/instagram-monitor. Его SQL RPC
instagram_monitor_profile_status содержит только SELECT. Новых критичных
находок в scope быть не должно.

Сразу после Publish в текущей сессии суперадминистратора выполнить новую
проверку: все 6/6 должны пройти, новые письма/очереди не создаются. Отдельный
вход в Preview и перенос токенов не нужны. До 6/6 и отдельных ПК/mobile
скриншотов опубликованных срока ЦБ2 и блока диагностики релиз не завершён.

Cloud compiler требует явного типа headers у тестового fetch-init; приняты
два приведения типов в release-health_test.ts. Они не меняют исполняемые
функции. Финальные CI проверяют дерево с этими приведениями целиком.

# Управление диалогом автопродаж

Дополнен существующий модуль `scripts/sales-knowledge/lib/dialogue-policy.mjs`.
Единый `evaluateReply` сохраняет проверки продукта, знаний, платного содержания,
прав Business, срока ответа, истории и доставки. Второй механизм разрешения
отправки не создаётся. Модуль пока не подключён к webhook/UI; сообщений не отправляет.

Новый режим кампании задаёт `require_activation`, `trigger_phrase` и при тесте
`owner_test`. Активация требует полной фразы в новом входящем, подтверждённой
предзаписи и выбранного диалога. В тесте допускается ровно один диалог.
Сравнение фразы нормирует только регистр/пробелы, без подстрок и поиска намерения.
Дубли, импорт, правки и эхо не активируют продажу. Версия активации привязана
к версии политики; новая редакция не разрешает старые диалоги автоматически.

События `manual_pause`, `silent_handoff`, `manual_resume` проверяют точный
Business-диалог. Передача человеку не содержит клиентского сообщения.
Продолжение сохраняет этап, контекст и факт старта, требует нового снимка
истории и подтверждённой границы уже отвеченных входящих. После ответа
человека получается WAIT_CUSTOMER; неотвеченный вопрос на паузе можно обработать.
Отказ, неизвестная доставка и активная отправка не снимаются продолжением.

Доверенный сервер обязан валидировать события и права оператора, получать
признак анкеты и утверждения из канонических источников. Нельзя брать эти
признаки из ответа модели или параметров браузера. Сохранение событий,
перехода и задания очереди выполняется атомарно по точному диалогу.
Перед отправкой заново читаются политика, история, права и состояние,
после чего обязательны `evaluateReply` и атомарный claim исходящего.
Смена режима/области/фразы/знаний повышает версию и отменяет старые задания.

Ещё не реализованы durable outbox/worker, подключение Business webhook,
различение manual/AI echo, защищённый серверный путь существующего поручения,
resolver предложения, контекст модели и UI управления. Их нельзя заменить
прямым invoke AI из webhook или отключением JWT у функции уведомлений.
Уже начатую отправку нельзя считать отозванной паузой; таймаут требует сверки,
а не слепого повторения. Для UI позже нужны опубликованные ПК/mobile проверки.

Проверка: `node --test scripts/sales-knowledge/dialogue*.test.mjs`.
13 новых сценариев плюс существующие проверки единой политики. Общий
GitHub release gate уже запускает все `scripts/sales-knowledge/*.test.mjs`.
Переписки, закрытые уроки и реальные настройки в этот код не включены.

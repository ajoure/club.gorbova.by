# Доплата по существующей рассрочке

## Проверенные границы

- Один original orders_v2 и один subscriptions_v2 на всю покупку. Ни новый
  REBILL-заказ, ни новая покупка для следующих взносов не создаются.
- Источник обязательства — согласованный meta.installment.effective_total_byn,
  а не текущая цена тарифа, offer_id или recurring_amount. Оплачено считается
  по уникальным подтверждённым payments_v2. Возврат/противоречие требует
  проверки: возвращённые деньги нельзя автоматически превратить в новый долг.
- 1326 − 442 = 884. Два оставшихся платежа: 442 + 442. При ручном
  переразбиении на три: 294.67 + 294.67 + 294.66, без увеличения обязательства.
- Provider-managed finite НЕ материализует installment_payments. Параллельный
  финансовый график создавать запрещено. Старые snapshots/счётчики не являются
  доказательством оплаты.
- failed_attempt у bePaid не финален: возможны повторные списания. Создать
  второй платёжный мандат рядом с ним без согласованной замены нельзя.
- Существующий bepaid-admin-create-subscription-link берёт текущий offer.amount
  и создаёт бесконечную подписку. Для finite intent он теперь закрыт guard-ом;
  доплата идёт только через отдельный repayment-контур.

## Реализованный контур

1. Единственный writer admin-create-public-link расширен режимом existing
   installment: quote по оригинальному заказу, затем link/create с payments:edit.
   Сервер сам выбирает точные order/sub/provider связи. Ссылка содержит
   неизменяемый fingerprint баланса/версии графика; новое создание не вызывает
   провайдера. Создание/перевыпуск/переразбиение аудируются и сериализуются
   короткой транзакцией с блокировкой исходного заказа.
2. public-checkout ответвляет этот тип ссылки ДО generic new-sale helper и
   повторно сверяет fingerprint/остаток/связи. Checkout резервируется CAS.
   Новый конечный bePaid-план создаётся на оставшиеся равные платежи. Старый
   мандат не отменяется до ввода новой карты: после первого успешного платежа
   webhook отменяет его, проверяет terminal state и помечает старую локальную
   проекцию ignore_provider_events, исключая двойные последующие списания.
3. Новый мандат привязывается к прежнему order/sub и имеет собственный
   remaining billing_cycles. Старый provider counter нельзя вычитать из нового.
   Для 2×442: infinite=false, billing_cycles=2, amount=44200, interval=30 days.
   Неравные суммы не представимы обычным uniform bePaid plan.amount: ручной
   график/разовые платежи поддерживаются отдельно, не округлять остаток вверх.
4. Webhook repayment-generation идёт после проверки подлинности, но до
   generic REBILL/grant/expiry. Upsert через канонический writer payments_v2;
   закрывать долг по сумме, а не только provider cycle. Не продлевать доступ
   за каждый взнос и не сокращать access_end_at при окончании списаний.
   Дубликат события должен повторно доводить progress до консистентного состояния.
   Старые отменённые мандаты не могут перезаписать новую привязку/график.
   Refund-событие этого tracking_id не считается взносом: оно уже сохранено
   каноническим webhook в reconcile queue с parent_uid и уходит в отдельную
   refund-сверку. Финансовый origin успешного взноса остаётся `bepaid`, а
   детализация repayment хранится в meta, поэтому платёж виден в отчётах.
5. UI в существующей рассрочке содержит «Создать ссылку», «Разовый платёж», «Автоплатежи»,
   остаток, оплачено, число оставшихся платежей, новый график до сохранения,
   отдельное явное согласие на замену старого мандата. Без новой покупки.
6. Локально обязательны unit/contract tests, app types/build, Deno check и edge
   contracts. Production rollout выполняется только после PR и Lovable review;
   реальные списания, отмены и создание клиентской ссылки не используются как smoke.

## Официальные контракты провайдера

- https://docs.bepaid.by/en/payment_management/subscriptions/subscriptions/
  failed_attempt предусматривает повторы; canceled — прекращение renewals.
- https://docs.bepaid.by/en/payment_management/subscriptions/plans/
  plan.amount задаёт равномерные списания; infinite=false + billing_cycles
  ограничивает их количество. Не выводить поддержку неодинакового последнего
  платежа из предположения о trial — требуется отдельный доказанный контракт.

До production rollout этот документ и тесты не являются E2E-доказательством.

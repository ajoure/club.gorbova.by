# Шаг 5: неизвестные оценки ИИ

При живой приёмке quotes успешно выделил четыре дословные цитаты, но needs
завершался `ai_result_rejected` / «Неверная оценка ИИ». Ответы и цитаты
сохранились. Полный ответ провайдера намеренно не записывается в логи;
конкретное некорректное поле прежняя диагностика не называла.

В prompt уточнён JSON-контракт: целое число 1–5 или null внутри объекта
оценки; rationale — строка. Для product fit без продуктовых источников дан
явный пример неизвестной оценки. Bare null также безопасно означает
«недостаточно данных»: числовые оценки не придумываются. Пропущенные поля,
строки вместо чисел, дроби, баллы вне диапазона и неверные обоснования
по-прежнему отклоняются; сообщение теперь называет поле, без содержимого
интервью или ответа модели. Проверки дословных цитат, покрытия всех источников,
уникальности и действительных product refs не меняются.

Только один managed deploy `training-custdev` после merge/CI и ревизии
плана Lovable. Маркер OPTIONS/POST: `bkb-step5-ai-scores-v2`. SQL, RLS,
Auth, config, уведомления, другие функции, платежи и доступы не меняются.
Shared contract/workspace импортируются только этим Edge-обработчиком;
frontend использует тот же контракт. Обычный frontend Publish допускается
только после проверки точного merged SHA и отсутствия чужих изменений.

Проверки: nullable и malformed оценки, сохранность quote IDs, prompt;
изолированный полный handler→БД→apply→submit→admin review с bare-null fit;
существующие RLS/CAS/history/rate-limit проверки. Живая приёмка с реальным
ИИ, сохранением ручных правок и сдачей проверяется отдельно после deploy.

# Явные основания ответа ИИ

PR468 исправил загрузку истории: production-синтетика new_client прошла6/6, graduate5/5. Повторная цепочка club_consultation остановилась на четвёртом шаге с invalid_customer_evidence. Это означает ссылку на недопустимый источник (продавец, кодовое слово, отсутствующий индекс или нечисловое значение), а не подтверждённый факт ошибки клиента. Конкретный индекс предыдущая версия не сохраняла при исключении.

Модель получала массив истории, но должна была сама посчитать индексы. Теперь у каждой реплики есть явный evidence_index, а отдельно передаётся customer_evidence_indices. Продавец и кодовое слово имеют null; допустимые числовые индексы сохраняют позиции в полной истории. История не обрезается, серверная проверка readAssessment остаётся прежней. Автоматических повторных запросов к модели нет.

В синтетическом режиме диагностическая сводка фиксируется до проверки, чтобы ошибка показывала конкретный неверный индекс и слот. Сводка содержит только разрешённые значения, числа и известные ID фактов; тексты сообщений и произвольный ответ модели не попадают в диагностику. В обычном runtime callback отсутствует.

Локально:21 целевой тест PASS, включая исходные правила диалога, техническое поручение и три проверки новых индексов/диагностики. Нужны полный GitHub gate, plan-only проверка, deploy только sales-runtime-worker и новый прогон синтетических сценариев. Миграций, изменения данных, конфигурации, кампании или UI нет. Предыдущий managed SQL112411 имеет идемпотентную автокопию120110; этот патч не меняет историю миграций.

Кампания OFF/HUMAN_HOLD, revision9, очередь0. Ни публикации, ни реальных сообщений/ссылок/платежей. Полная готовность по-прежнему требует оставшихся серверных тестов, опубликованного UI и согласованных бизнес-настроек ЦБ21.

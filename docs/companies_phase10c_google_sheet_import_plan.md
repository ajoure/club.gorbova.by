## Идемпотентность и stop-guards

1. Основное сопоставление: `country=BY + normalized UNP`.
2. Вторичное сопоставление: существующий `amocrm` external ID.
3. Название, email и телефон сами по себе не дают права на автоматическое
   объединение; неоднозначность уходит в `conflict`.
4. Повторный импорт той же строки не создаёт вторую компанию, заметку или
   задачу. Для заметки и задачи используется ключ источника + номер строки.
5. Руководитель не становится `profiles` и не создаётся как обычный контакт
   без подтверждённых контактных данных.
6. Задача назначается только после точного поиска активного пользователя
   «Полина Асманта». Ноль или несколько совпадений — hard stop для задач, но
   не для безопасного импорта компаний/заметок.
7. Реальные записи разрешаются отдельным approval-gate после отчёта dry-run.

## Этапы выполнения

1. Read-only extraction ограниченными диапазонами и нормализация адаптером CSV.
2. `crm_company_external_reconcile_preview` для классификации `create`,
   `link_candidate`, `existing`, `conflict`, `skip`.
3. Отчёт с totals, конфликтами, пустыми UNP, найденными amoCRM IDs,
   заметками и датами callback.
4. Контрольная пачка без задач callback.
5. Пакетный импорт с audit/idempotency ledger.
6. Отдельная пачка задач callback после проверки точного assignee ID.
7. Reconciliation: число строк, компаний, заметок, external IDs, задач,
   конфликтов и пропусков.

## Phase 10E — controlled apply

- `crm_company_sheet_import_batch_start` принимает только нормализованный JSON-массив,
  сохраняет preview-batch и гарантирует, что этот вызов ничего не пишет в CRM.
- `crm_company_sheet_import_batch_apply` требует `_confirm=true`, выполняет не
  более 100 строк за вызов и продолжает с cursor после любого следующего вызова.
- `company_import_ledger` уникален по `source + source_key`: повторная строка
  получает `skipped`, а не вторую компанию/заметку/задачу.
- Руководитель записывается в canonical-реквизиты и `company_notes`; LPR
  структурированный массив — только в `company_contact_persons`, строковое поле
  без структуры — заметкой.
- Если в batch есть callback-даты, пользователь «Полина Асманта» должен
  разрешиться ровно в один профиль; иначе apply останавливается до любых записей.
- Нормализованный `callback_at` должен быть ISO-датой или ISO timestamp; дата без
  времени трактуется как 09:00 в `Europe/Minsk`.

## Companies parity UI follow-up

- `/admin/companies` работает в full-height режиме: вертикальная прокрутка
  принадлежит странице, а горизонтальная — только канонической таблице.
- Сортировка по названию, public ID и дате создания использует тот же RPC
  `search_companies`, что и фильтры/пагинация; настройки колонок, выбор строк,
  resize и drag-and-drop сохраняются отдельно от контактов.
- Вкладка «Лента» компании использует канонический `ContactFeedTab` с теми же
  фильтрами, поиском, композером заметок/задач и предпросмотром файлов; запросы
  переключаются на `company_feed_list`, а файлы хранятся в `company_files`.
- Голосовые файлы компании проходят те же AI-расшифровку и пересылку в Telegram,
  что и контактные: Edge Functions определяют исходную таблицу файла и не
  пытаются читать company-файл как контактный.

## Rollback

Импорт должен быть связан единым `source_batch_id`; откат удаляет только записи
этого batch, не затрагивая существующие canonical реквизиты, документы,
коммуникации или пользовательские заметки.

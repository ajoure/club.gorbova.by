# Проверенная сборка конференции с пропусками субтитров

Этот путь предназначен для одного источника CB20, у которого исходный русский
VTT сохранён в `course_caption_gap_audits`, шесть результатов продолжения
собраны, а первый участок остался `uncertain`. Он не вызывает STT повторно и
не изменяет другие 59 текстов. Результат остаётся `paid_private/unreviewed`:
это корпус курса, не опубликованный ответ продавца.

## Решение редактора

Владелец курса смотрит каждый из семи отрезков в исходном плеере. Для каждого
он выбирает `speech` с исправленным текстом либо `non_speech` с `text:null`,
указывает краткую причину и свой подтверждённый `reviewer_id`. Нельзя принимать
ASR автоматически: алфавит ответа не доказывает точность. Первый участок с
ответом без кириллицы требует отдельного прослушивания. Частные тексты, ID и
ссылки не входят в GitHub и публичный отчёт.

Приватный JSON-файл решения (`0600`) имеет поля `schema_version:1`,
`mode:"reviewed_gap_assembly"`, `audit_id`, `reviewer_id`, `decisions` — ровно семь
объектов в порядке `part_index`. Каждый объект: `part_index`, `kind`, `text`,
`evidence_sha256`, `audio_sha256`, `reviewer_id`, `note`. Хеши берутся из
закрытого read-back исходного аудита, а не переписываются вручную по догадке.

## Managed-порядок

После GitHub review/merge и plan-only ревизии Lovable применяет только новую
миграцию. Проверяются service-only права RPC и owner-only чтение таблицы.
В каноническом Lovable Cloud SQL из исходного PR #545 уже применён один раз:
managed-журнал зарегистрировал его как `20260925130513`, а синхронизация
создала файл `20260925130513_8838204f-2a91-406e-90c5-d7a510a87ca9.sql`.
Исходный файл с номером `20260925123647` удалён из GitHub после сверки
SQL (единственное различие — завершающий перевод строки), чтобы он не был
ошибочно выполнен повторно и не ломал clean replay. Проверять состояние нужно
по managed-журналу и read-back таблицы/RPC. Прямой `supabase db push` к этой
базе по-прежнему запрещён правилами проекта.
Запускать скрипт можно только в каноническом managed-окружении с существующими
`COURSE_KB_OWNER_ID`, подключённой Kinescope-интеграцией и сервисным доступом.
Секреты не выводятся и не переносятся в локальный Codex. Если окружение не
предоставляет эти настройки, выполнение останавливается.

1. `publish-reviewed-gaps.mjs --managed-lovable --mode dry-run
   --original-manifest <private-original> --review-file <private-review>
   --report <new-private-report>` перечитывает источник и сохранённый аудит.
   Отчёт содержит только хеши и счётчики, без текста/ссылок. STT и записей нет.
2. Владелец проверяет решения и утверждает SHA256 **точного файла отчёта**.
   Изменившаяся версия видео, VTT, привязки, любой из семи результатов или
   решение редактора делают прежнее утверждение недействительным.
3. `--mode execute --manifest <same-report>
   --approved-manifest-sha256 <approved-hash>` с остальными теми же аргументами
   повторяет все чтения и создаёт ровно одну запись через сервисный RPC.
   RPC снова проверяет права, состояние аудита, результаты, хеши и отсутствие
   существующего текста/задачи STT. Повтор идентичного вызова — read-back
   `reused:true`; иной результат конфликтует.
4. Проверить приватный read-back: одна запись, точный SHA256, `paid_private`,
   `unreviewed`, `origin=provider_subtitles`, неизменные исходные семь частей,
   ноль новых STT-вызовов. Затем отдельно утверждать краткие sales-safe факты,
   если они нужны для консультаций.

Этот путь не считает конференцию проверенной для ответов клиентам и не включает
кампанию автопродаж. При отсутствии редакторского решения публикации нет.

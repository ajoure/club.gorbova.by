# Sprint 11 · C5-I — Template Workflow UX

Status: **Implemented (UI)**. C5-J (PDF as primary output) — **BLOCKED on PDF converter dependency** (см. раздел в конце).

## Проблема
- После загрузки .docx непонятно, что делать дальше.
- Кнопка «Сделать текущей» при ошибке показывала сырой `Edge Function returned a non-2xx status code`.
- «Расширенная разметка (legacy)» выглядела как основной путь, но для уже валидного FLD-шаблона все её кнопки были выключены — активировать шаблон было невозможно.
- На основной панели висели технические блоки «Найдено плейсхолдеров» и «Текст документа (первые 3000 символов)», которые шумят и не помогают принять решение.

## Что сделано (фактически)

### `src/components/ai-documents/StrictDocumentTemplatesManager.tsx`
1. **Авто-валидация после загрузки.** В `handleUpload` после `fetchAll()` подтягивается только что созданная `document_template_versions` строка по `(template_id, storage_path)` и сразу вызывается `openPreview(...)`. Пользователь видит итоговый статус (`valid` / список ошибок) без ручного клика по версии.
2. **Действие переименовано:** `Сделать текущей` → **`Активировать шаблон`**, `Уже текущая` → `Уже активен`.
3. **Validation-summary стал человеческим:**
   - `Validation: valid` → `Шаблон проверен — можно активировать`.
   - `Validation: invalid (N)` → `Найдено ошибок: N` + список причин с кодами.
   - Подпись `recognized: X · raw: Y` → `FLD-полей: X · всего плейсхолдеров: Y` (вторая часть скрывается, если значения совпадают).
4. **Добавлена кнопка `Скопировать плейсхолдеры`** (для валидных версий) — копирует список `{{field:FLD-…}}` в буфер.
5. **Шумные блоки удалены с основного экрана:** «Найдено плейсхолдеров» и «Текст документа (первые 3000 символов)» больше не отображаются. Полный документ доступен в окне «Проверка и исправление плейсхолдеров».
6. **Legacy-кнопка переименована:** `Расширенная разметка (legacy) · Не рекомендуется — редактируйте в Word` → **`Проверка и исправление плейсхолдеров` · `Открывайте, только если в шаблоне есть ошибки`**. Стиль `ghost` → `outline` (не выглядит как deprecated-помойка).
7. **Нормализация ошибок активации.** Введён локальный `mapActivationError(raw, data)` поверх `normalizeEdgeFunctionError`:
   - `cannot_activate_invalid_version` → «Шаблон содержит ошибки в плейсхолдерах. Откройте «Проверка и исправление плейсхолдеров» и исправьте их.»
   - `cannot_activate_unmarked_version` → «Шаблон не размечен. Откройте «Проверка и исправление плейсхолдеров».»
   - `forbidden` → «Недостаточно прав для активации шаблона.»
   - `unauthorized` → «Сессия истекла. Войдите заново.»
   - `version_not_found` → «Версия шаблона не найдена. Обновите список.»
   - всё остальное — через `normalizeEdgeFunctionError`. Сырой `non-2xx status code` пользователю больше не показывается.

## C5-J — Dependency gate (PDF as primary output)

Status: **BLOCKED — нет DOCX→PDF converter secret**.

Проверка `secrets--fetch_secrets` показала: в проекте **нет** ни `GOTENBERG_URL`, ни `CLOUDCONVERT_API_KEY`, ни иного DOCX→PDF endpoint. По правилам плана C5-J:

> «не начинать C5-J без реального converter proof»

C5-J не запускался. Текущая генерация в `DealDocumentsPanel` остаётся DOCX (поэтому кнопка лейблится нейтрально — `Сформировать документ`, без ложного обещания PDF). Никакой HTML→PDF подмены не делалось — это бы создало второй шаблонный движок поверх DOCX.

### Что нужно от пользователя для запуска C5-J
1. Подключить безопасный конвертер DOCX→PDF (Gotenberg / CloudConvert / аналог) и добавить secret с URL/API key.
2. После добавления secret — выполнить dry-run (тестовый DOCX → PDF, проверить `application/pdf` и размер > 10 KB, убедиться, что bucket `documents` принимает `application/pdf` — уже подтверждено).
3. Только после этого менять `canonical-document-generate-strict`:
   - PDF становится primary `file_path/file_mime/file_name`;
   - технический DOCX уезжает в `meta.docx_storage_path`;
   - при ошибке PDF-конверсии — `status='failed'`, тот же `idempotency_key` повторяет конверсию для того же документа без выдачи нового номера.

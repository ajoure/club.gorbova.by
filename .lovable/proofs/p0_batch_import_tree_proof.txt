## 4. Lineage: batch_start → row

Parent lineage for ALL row-level rows:
```
parent_event_key = batch_start.source_event_key
parent_execution_key = batch_start.execution_key
```

Single-row parent match SQL:
```sql
SELECT r.id, r.source_event_key, r.parent_event_key, r.parent_execution_key,
       b.source_event_key AS batch_event_key, b.execution_key AS batch_exec_key
FROM access_grant_ledger r
JOIN access_grant_ledger b
  ON b.source_event_key = r.parent_event_key
  AND b.execution_key = r.parent_execution_key
  AND b.action_type = 'batch_start'
WHERE r.action_type != 'batch_start'
  AND r.source_event_key LIKE 'bepaid-import:%:row:%'
   OR r.source_event_key LIKE 'gc-import:%:row:%';
```

## 10. Fallback hash contract

Implementation (identical in both files — byte-identical drift guard confirmed):
```typescript
async function stableRowHash(payload: Record<string, unknown>): Promise<string> {
  const sorted = JSON.stringify(
    Object.keys(payload).sort().reduce((acc, k) => { acc[k] = payload[k]; return acc; }, {} as Record<string, unknown>)
  );
  const buf = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(sorted));
  return Array.from(new Uint8Array(buf)).map(b => b.toString(16).padStart(2, '0')).join('').slice(0, 16);
}
```

Properties:
- Deterministic: same payload → same hash ✅
- No timestamp in discriminator ✅
- No random in discriminator ✅
- No index in discriminator ✅
- Identical implementation in both files (byte-identical) ✅
- sha256(JSON.stringify(sorted_keys_payload)).slice(0, 16) ✅

## 11. Per-row catch = mandatory failed ledger (stage-based)

Both imports:
- Each row processed in individual try/catch
- `currentStep` variable tracks current stage
- catch block writes failed ledger row with:
  - failed_at_step: currentStep (actual stage, not generic 'row_processing')
  - error_message: actual error message

- Failed ledger write itself is wrapped in try/catch to prevent cascade failure

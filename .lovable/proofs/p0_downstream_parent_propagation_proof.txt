## 5. Idempotent Skip Guard: execution_key = null

### Grant paths (grant-access-for-order → telegram-grant-access)
- If `writeLedgerEntry` returns `execution_key = null` (idempotent skip):
  - Recovery: re-read existing row by `source_event_key` to get `execution_key`
  - Pass recovered execution_key as `parent_execution_key` downstream
  - `_from_primary_path = true` still set (lineage recovered)

### Queue meta (subscription-charge → telegram_access_queue)
- If `renewLedgerResult.execution_key` is null/undefined:
  - Conditional spread `...(renewLedgerResult?.execution_key ? { meta: ... } : {})` → meta field NOT included in upsert
  - Existing `meta` on conflict row is NOT overwritten with null
  - Queue processor handles `null` meta gracefully (backward compatible)

### Revoke paths (subscription-charge trial_expire, subscriptions-reconcile, admin-actions)
- If `executeRevoke` returns `executionKey = null`:
  - Parent keys passed as `null` to downstream
  - `_from_primary_path` NOT set for revoke downstream (revoke writes own ledger)
  - No crash, no drift

## 6. Single-Row Parent Match SQL

```sql
-- Lineage verification: child rows must match parent by BOTH keys simultaneously
SELECT 
  child.id AS child_id,
  child.source_event_key AS child_event_key,
  child.parent_event_key,
  child.parent_execution_key,
  parent.id AS parent_id,
  parent.source_event_key AS parent_event_key_actual,
  parent.execution_key AS parent_execution_key_actual
FROM access_grant_ledger child
JOIN access_grant_ledger parent
  ON parent.source_event_key = child.parent_event_key
 AND parent.execution_key = child.parent_execution_key
WHERE child.parent_event_key IS NOT NULL;
```

**Rule**: Two separate EXISTS checks are NOT acceptable as primary lineage proof.
Only the single-row JOIN on both fields simultaneously validates the parent-child relationship.

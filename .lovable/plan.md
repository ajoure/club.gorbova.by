## Проблема

UI вкладки «Ссылки» показывает 0 строк, хотя в `payment_links` фактически 12 записей. Корень: на view `payment_links_enriched_v` не выданы `GRANT SELECT` ролям `authenticated` / `anon`. View создан с `security_invoker=on` и RLS на базовой таблице корректна (`has_role(auth.uid(),'admin')`), но без табличного GRANT PostgREST/клиент даже не доходит до RLS-проверки — результат пустой.

Про «подтянуть ссылки из bePaid» — это невозможно по архитектуре: bePaid не хранит «ссылки на оплату» как отдельную сущность. Ссылки — это наш `payment_links` (canonical SOT). bePaid знает только транзакции, и они уже отражены в `orders_v2` через webhook. Ничего «исторического по ссылкам» из bePaid вытянуть нельзя — там этого нет.

## Что делаю (одна точечная миграция, add-only)

Выдаю недостающие привилегии на view, чтобы клиент-сайд через PostgREST мог его читать (RLS базовой таблицы продолжает защищать данные):

```sql
GRANT SELECT ON public.payment_links_enriched_v TO authenticated;
```

`anon` намеренно не даю — публичный доступ к журналу ссылок не нужен. RLS на `payment_links` остаётся прежней (`admin` может читать, остальные — нет), `security_invoker=on` гарантирует, что проверка идёт от текущего пользователя.

## Что проверяю после фикса

1. SELECT из view от имени `authenticated` возвращает 12 строк для admin-пользователя.
2. UI `/admin/payments/links` показывает все 12 исторических ссылок.
3. Для не-admin пользователя view по-прежнему пустой (RLS не сломана).

## Что НЕ делаю

- Не трогаю RLS на `payment_links`.
- Не меняю определение view.
- Не трогаю edge functions, writers, webhook, consume, grant-access.
- Не пытаюсь «синкать ссылки из bePaid» — таких сущностей у провайдера нет.
- Не выдаю GRANT для `anon`.

## Пояснение по bePaid (для отчёта)

- bePaid API: `tokens`, `payments`, `subscriptions` — это транзакции и подписки, не ссылки.
- Наши ссылки `/pay/<token>` живут только в нашей БД.
- Любая «история» ссылок уже есть в `payment_links` + `audit_logs` (`payment_link.created/updated/invalidated/link_consumed`).
- Recovery исторических ссылок из внешнего источника не предусмотрен и не нужен.

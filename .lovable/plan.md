## 3. Минимальный план (предложение для Codex)

Блокеры до начала:
- (а) Владелец указывает точный UUID бонусного урока или создаёт его. Иначе бонус не выдаётся, курс целиком не выдаётся никогда.
- (б) Владелец подтверждает канал «Тайное свидание» и добавляет @gorbovabybot администратором с правом одобрять заявки. До этого числовой ID и права — UNKNOWN.
- (в) Утверждены тексты уведомлений.

Шаги, каждый — отдельный PR со своей проверкой:
1. **Анкета первой, черновик.** Ответы сохраняются локально по ключу «страница + форма» и восстанавливаются после перезагрузки. Очищаются только после успешной отправки. Персональные данные на сервер до отправки не уходят.
2. **Вход по коду после ответов.** Для гостя форма в конце показывает существующий `InlineEmailOtpForm` (6 цифр, без пароля), затем отправляет анкету с полученной сессией. Существующие лимиты переиспользуются.
3. **Канонический контакт.** Профиль определяется только по токену входа, как сейчас. В анкете сохраняются все 15 ответов. Продукт и тариф берутся с сервера из опубликованной формы. Сделка — существующий дедуп «профиль + продукт + воронка + этап».
4. **Одна идемпотентная отправка.** Клиент передаёт ключ отправки. Сервер хранит его в метаданных, повтор возвращает прежний результат. Плюс защита от двойного нажатия.
5. **Бонус — только урок.** После блокера (а) — правило доступа существующего типа только на этот урок или модуль для тарифа предзаписи. Без доступа к курсу и других уроков.
6. **Бот поддержки и вступление.** На странице «спасибо» вместо общей ссылки — кнопка привязки через `telegram-link-manage`. Канал переводится в режим заявок на вступление. Одобряются только привязанные пользователи с анкетой и продуктом предзаписи — через существующую обработку заявок, после блокера (б).
7. **Уведомления без дублей.** Одно правило автоматизации воронки на событие «сделка создана» или «вход на этап», действие send_telegram. Ключ идемпотентности привязан к задаче, как уже сделано в worker. Аудитория — только по продукту предзаписи, без купивших основной поток, если владелец так решит. До включения — проверочный прогон на тестовом пользователе с отдельного разрешения.
8. **10 ссылок-источников.** 10 ссылок вида `?src=<код>` (и utm). Форма сохраняет первый источник локально и передаёт его при отправке. Сервер принимает только код из разрешённого списка, кладёт его в метаданные анкеты и в поле или активность сделки, а в CRM добавляется фильтр по нему.

## 4. Проверки (DoD)

- Тесты: восстановление черновика, повторная отправка не создаёт вторую анкету или сделку, выдаётся только бонусный урок, один источник на анкету.
- Скриншоты анкеты и «спасибо» на ПК и мобильном после Publish.
- Сверка «до/после»: ни одного нового доступа, кроме бонусного урока.

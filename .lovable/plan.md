# План: Runtime proof + восстановление редактирования уроков + очистка формы

## 1. Текущее состояние

### Что уже работает в коде

- **Lesson edit dialog** (`AdminTrainingLessons.tsx`, строки 918-947): карандаш вызывает `openEditDialog` → заполняет `formData` → рендерит `LessonFormContent` с полями title, slug, description, video_url, completion_mode, is_active, thumbnail → кнопка «Сохранить» вызывает `handleUpdate` → `updateLesson(id, data)` → `supabase.update().eq("id", id)` → `fetchLessons()` для invalidation.
- **Runtime filtering** (`useTrainingContentRules.ts`): `useActiveTrainingContentRules` загружает правила по entitlements/subscriptions пользователя → `resolveTrainingContentFilter` выбирает лучшее правило (tariff > product) → `isModuleVisible`/`isLessonVisible` фильтруют контент в `useTrainingModules`, `useContainerLessons`, `useSidebarModules`.
- **DB constraint** расширен на `training_content`.

### Что требует proof

- Фактическое создание training_content rule через UI и подтверждение записи в БД.
- Фактическое редактирование урока: изменение title → сохранение → проверка в списке и после reload.
- Runtime: non-admin видит только разрешённый контент.

## 2. Задачи

### A. Runtime proof: training_content rule end-to-end

**Цель**: доказать, что новый контур доступа работает не только в БД, но и в клиентском UI.

**Действия**:

1. Через browser tools залогиниться как admin → открыть продукт → вкладка «Доступы» → создать training_content rule.
2. Проверить запись в `access_rules` через SQL: `SELECT id, target_ref, conditions FROM access_rules WHERE grant_target_type = 'training_content'`.
3. Проверить 3 сценария в коде/данных:
  - **Полный доступ**: rule с `access_mode: "full"` → `resolveTrainingContentFilter` возвращает `{mode: "full"}` → все модули/уроки видны.
  - **Частичный — один модуль**: rule с `access_mode: "partial"`, `allowed_module_ids: [moduleId]` → только этот модуль виден через `isModuleVisible`.
  - **Частичный — один урок**: rule с `allowed_lesson_ids: [lessonId]` → только этот урок виден через `isLessonVisible`.

**Если ошибка**: зафиксировать console/network и исправить.

### B. Proof: редактирование метаданных урока

**Цель**: доказать, что карандаш открывает рабочий edit-dialog и изменения сохраняются.

**Действия**:

1. Через browser tools открыть модуль с уроками → нажать карандаш у урока.
2. Изменить title (убрать «Копия»), сохранить.
3. Проверить:
  - toast «Урок обновлён»;
  - обновление в списке без reload;
  - после reload — название не откатывается;
  - SQL post-check: `SELECT title FROM training_lessons WHERE id = '...'`.

**Если не работает**: зафиксировать console errors, network response, и исправить. Вероятные причины:

- RLS блокирует UPDATE → миграция policy;
- Re-render теряет фокус → проверить key stability;
- Mutation response не инвалидирует кэш → проверить `fetchLessons()`.

### C. Очистка формы урока

### E. Модель активности урока

**Факт из кода**: у урока есть собственный `is_active` (строка 359-364 в `LessonFormContent`, строка 546 в `openEditDialog`). Это поле из таблицы `training_lessons`.

**Runtime влияние**: в `useContainerLessons.ts` используется `isLessonAllowed` (алиас `isLessonVisible`) — это фильтрация по access rules, а не по `is_active`. Нужно проверить, есть ли отдельный фильтр по `is_active` в клиентских хуках.

**Вывод для UI**: бейдж «Неактивен» в tree picker корректен, если `is_active = false` в БД. Это не блокирует выбор в rule — tree picker показывает все модули/уроки для выбора.

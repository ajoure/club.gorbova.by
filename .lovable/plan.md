# План (READ-ONLY / PLAN-ONLY): contact-send-button

Задача изолирована от main `eee55e9f310c1a3c18bd0876163e6d0ebd7caed3`. Ничего не менялось: без кода, коммитов, миграций, данных, ролей, permissions, деплоя функций, Publish, сообщений и вызовов Telegram.

## Что проверено на production

- Локальный HEAD = `eee55e9f310c1a3c18bd0876163e6d0ebd7caed3`, дерево чистое.
- Опубликованный бандл: входной файл `assets/index-CamOqLqA.js`; чанк контакт-центра `ContactDetailSheet-XhXLCLg5.js` содержит и ключ запроса `telegram-bots-for-chat`, и вызов `list_operational_telegram_bots`. То есть опубликованная версия уже использует безопасный RPC, а не прямой SELECT таблицы ботов.
- Функция `list_operational_telegram_bots`: SQL, STABLE, SECURITY DEFINER, owner `postgres`, `search_path=''`, EXECUTE выдан `authenticated` и `service_role`. Проекция безопасная: возвращает только id, имя, username, bot_id, статус, признак primary, даты, а `error_message` жёстко заменён на NULL. Токенов и конфигурации не отдаёт.
- Гейт внутри RPC: `auth.uid() IS NOT NULL` и любой из доступов view к разделам communication / contacts / club-members / training / products, либо `entitlements.manage`. Для ролей super_admin и admin `has_admin_section_access` возвращает true безусловно.
- Агрегаты по ролям (без имён и PII): RBAC v2 — super_admin 2, admin 7, менеджер 5, support 1, обычные пользователи 233. Legacy `user_roles` — admin 2, user 9.
- Боты: всего 4, все со статусом active, один primary. Данных для дропдауна в БД достаточно.
- Ошибки: в логах Postgres за 2 суток нет ошибок по функции и по таблице ботов. Анонимный POST к RPC даёт 401 `42501` — значит функция есть в schema cache, гейт работает, публичного доступа нет.
- Таблица ботов после PR431–436: нет ни одного табличного гранта, действует restrictive-политика только для super_admin поверх старых permissive-политик. Любой прямой SELECT из клиента теперь возвращает ошибку доступа или пусто.
- Гейт отправки в `telegram-admin-chat` (только чтение кода, без вызова): 401 без Bearer, далее 403 если нет admin/superadmin и нет communication:view, для мутаций дополнительно требуется communication:manage. Для владельца и админов отправка не блокируется. За 2 суток вызовов этой функции в логах нет, то есть кнопка не нажималась и запрос не уходил.

## Причина

Кнопка «Отправить» блокируется только клиентом: `disabled` включает условие «не выбран ни бот, ни бизнес-аккаунт», а селектор отправителя вообще не рендерится, если список активных ботов пуст. Список ботов грузится запросом с `data = []` по умолчанию: любая ошибка запроса даёт пустой массив, без сообщения и без повтора вручную. Итог — молчаливое «нет отправителя» и навсегда серая кнопка при набранном тексте.

Конкретные источники пустого списка, совместимые со скриншотом:

1. Основная версия: давно открытая вкладка со старым бандлом (до перехода на RPC) продолжает делать прямой SELECT таблицы ботов. После PR431–436 грантов на таблицу нет, действует restrictive-политика super_admin, ответ — ошибка доступа, которую UI проглатывает. Обновление страницы подтягивает новый бандл и должно вернуть дропдаун. Это проверяется одним hard reload без каких-либо изменений.
2. Вторая версия: сотрудник вне super_admin/admin, у которого есть доступ к диалогам, но нет ни одного из шести доступов гейта RPC (в частности, доступ, выданный только на ресурс «интеграции → telegram», гейтом не учитывается). Тогда RPC штатно вернёт 0 строк, и UI снова молча покажет пустой селектор.
3. Третья версия: разовая сетевая ошибка или истёкший токен на этом запросе — симптом идентичен, потому что ошибка не показывается.

## План безопасного исправления (Codex, отдельный PR, только фронтенд)

1. Перестать прятать ошибку: убрать молчаливый `data = []`, различать «загрузка», «ошибка», «пустой список».
2. При ошибке показывать в области отправителя короткий текст ошибки и кнопку «Повторить»; кнопка отправки при этом остаётся неактивной, но причина видна.
3. При успешном ответе с нулём ботов показывать явное «нет доступных отправителей — недостаточно прав», а не пустоту.
4. Не менять серверный гейт RPC и права в этом PR. Если подтвердится версия 2, расширение гейта делается отдельной задачей и отдельной миграцией.
5. Регресс-тесты: ошибка запроса → видимая ошибка и «Повторить»; пустой список → понятная подсказка; список с активными ботами → селектор виден и кнопка активна при непустом тексте.

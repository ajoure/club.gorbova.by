# FIX — Сохранение позиции скролла при навигации назад и переключении вкладок

## Проблема

Текущий фикс в `ScrollToTop` (не вызывать `scrollTo(0,0)` при POP-навигации) — необходимый, но **недостаточный**. В SPA при навигации назад:

1. Компонент страницы **размонтируется** (unmount) при уходе
2. При возврате (POP) компонент **монтируется заново** — scroll = 0
3. Контент загружается асинхронно (React Query, lazy loading)
4. `scrollRestoration = 'manual'` отключает попытки браузера восстановить позицию

Результат: даже без принудительного `scrollTo(0,0)`, страница всё равно показывается сверху.

Дополнительно: при переключении вкладок браузера (Excel → обратно), если Supabase решит обновить токен — `onAuthStateChange` может вызвать ре-рендер, хотя scroll обычно сохраняется.

## Решение

Реализовать ручное сохранение/восстановление позиции скролла:

```text
┌─ Навигация PUSH ─────────────────────────┐
│ 1. Перехватить beforeunload / navigate    │
│ 2. Сохранить scrollY в sessionStorage     │
│    по ключу pathname                      │
└───────────────────────────────────────────┘

┌─ Навигация POP ──────────────────────────┐
│ 1. ScrollToTop НЕ вызывает scrollTo(0,0) │
│ 2. После рендера контента —              │
│    восстановить scrollY из кеша           │
│ 3. Использовать requestAnimationFrame     │
│    + задержку для ожидания DOM            │
└───────────────────────────────────────────┘
```

## Изменения

### 1. `src/components/layout/ScrollToTop.tsx` — полная замена

Расширить компонент:

- **При каждом изменении pathname**: сохранять предыдущую позицию скролла в `sessionStorage` (ключ = предыдущий pathname)
- **При POP-навигации**: достать сохранённую позицию и восстановить через `requestAnimationFrame` с небольшой задержкой (50–100ms), чтобы контент успел отрендериться
- **При PUSH/REPLACE**: скроллить в начало (как сейчас)
- **Убрать `scrollRestoration = 'manual'**` — оставить `'auto'` как fallback, наша логика будет работать поверх

Ключевые детали:

- Хранить максимум 50 записей, чистить старые
- Использовать `useRef` для предыдущего pathname, чтобы сохранять позицию ПЕРЕД сменой маршрута
- Для восстановления — retry 3 раза с 100ms интервалом (дождаться пока контент загрузится и DOM вырастет до нужной высоты)

### 2. Без изменений в других файлах

- `KvestLessonView.tsx` — не трогаем (свои scrollToBlock привязаны к действиям пользователя)
- `LibraryLesson.tsx` — не трогаем (scrollTo при seekTo видео — конкретное действие)
- `DashboardLayout.tsx` — не трогаем
- `PullToRefresh.tsx` — не трогаем

## Не делаем

- Не кешируем DOM/компоненты (слишком дорого по памяти)
- Не меняем auth flow

- При переходе на новую страницу — скролл в начало (как раньше)
- При возврате назад через кнопку браузера — позиция скролла восстанавливается
- Работает с асинхронной загрузкой контента (retry до 3 раз)
- Работает во всех разделах: уроки, квесты, библиотека, настройки

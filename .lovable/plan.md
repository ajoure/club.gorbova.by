

# План: Исправить отображение токенов в истории рассылок

## Проблема
В истории рассылок отображается сырой шаблон с токенами (`{{first_name}}, привет 👋`) вместо читаемого текста. Это происходит потому, что `message_preview` сохраняется из исходного шаблона до подстановки переменных.

## Результат рассылки
Рассылка прошла успешно: **127 отправлено, 0 ошибок**. Все сообщения доставлены.

## Решение

### Файл: `supabase/functions/telegram-mass-broadcast/index.ts`
- Строка 405: заменить `message.substring(0, 50)` на версию с заменёнными токенами
- Создать «демо-превью»: подставить общие токены заглушками (убрать `{{first_name}}`, `{{full_name}}` и т.д.) чтобы превью выглядело чисто
- Логика: взять `message`, пропустить через `resolveSystemTokens`, затем убрать оставшиеся контактные токены (`{{first_name}}` → пустая строка), взять первые 80 символов

### Файл: `supabase/functions/email-mass-broadcast/index.ts`
- Применить аналогичную логику для `subject` / preview если сохраняется в audit_logs

### Файл: `src/components/admin/communication/BroadcastsTabContent.tsx` (фронтенд fallback)
- Добавить клиентскую очистку: если `message_preview` содержит `{{...}}`, заменить токены на пустые строки для отображения — на случай старых записей

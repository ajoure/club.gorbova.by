## Диагностика

Проверил `supabase/functions/telegram-mass-broadcast/index.ts` и БД:

1. **Корень проблемы (строки 322-343):** Edge-функция всегда берёт **первого попавшегося** активного бота из `telegram_bots`:
  ```ts
   const { data: bots } = await supabase
     .from('telegram_bots')
     .select('bot_token_encrypted')
     .eq('status', 'active')
     .limit(1);
   const botToken = bots[0].bot_token_encrypted;
  ```
   Параметр `filters.bot_ids` в интерфейсе объявлен (строка 71), но **нигде не используется**. Поэтому какие бы боты ни выбирал пользователь в UI («Боты для отправки: Выбрано: 3»), отправка всегда идёт с одного и того же бота — того, который вернётся первым из БД (видимо, `gorbovabybot`/основной).
2. **Аудитория получателей** не сегментируется по ботам. Сейчас функция загружает ВСЕХ юзеров с непустым `profiles.telegram_user_id` (строка 241-245) и отправляет им всем с единственного бота. Нет фильтрации по тому, через какого бота юзер реально подписан/связан.
3. **В БД есть колонка для сегментации:** `profiles.telegram_link_bot_id` — указывает, через какого бота пользователь привязал свой Telegram. Это и есть SoT для определения «к какому боту относится получатель».
4. **Активных ботов 4:** `gorbovabybot`, `gorbova_bot`, `Gorbova_club_bot`, `gorbova_gc_bot`. На скриншоте «основной» помечен `gorbovabybot` — он же `is_primary` (предположительно), и именно он попадает в `LIMIT 1` без `ORDER BY`.
5. **Фильтры `bot_ids` из UI** уже корректно собираются в `BroadcastsTabContent.tsx` (строки 938-955) и должны передаваться в payload, но edge-функция их игнорирует.

## Что меняем

### 1. `supabase/functions/telegram-mass-broadcast/index.ts`

**A) Резолв списка целевых ботов:**

- Если `filters.bot_ids` непустой — загружаем именно эти боты (`id, bot_token_encrypted, is_primary, bot_username`), отфильтровав по `status='active'`.
- Если `filters.bot_ids` пустой — fallback на основного бота: `WHERE is_primary = true AND status='active'`. Если основного нет — берём первого активного с `ORDER BY created_at`.

**B) Сегментация получателей по бот-привязке:**

- В выборку `profiles` добавить `telegram_link_bot_id`.
- Для каждого выбранного бота отправлять только тем профилям, у которых `telegram_link_bot_id = <bot.id>`.
- Профили с `telegram_link_bot_id IS NULL` (старые/неизвестные) — отправлять только если выбран основной бот, и только с него (один раз, чтобы не дублировать).
- Логика админов (всегда включаются): админы тоже получают сообщение через тот бот, к которому привязаны; если `telegram_link_bot_id` пуст — через основной.

**C) Цикл отправки:** перестраиваем — внешний цикл по выбранным ботам, внутренний по подходящим профилям. Каждый recipient получает ровно одно сообщение от «своего» бота. Это исключает текущее поведение, когда «основной бот шлёт всем подряд».

**D) Логирование:** в `telegram_messages.bot_id` записывать реальный `bot.id`, с которого отправлено сообщение (сейчас всегда пишется `activeBotId` первого бота).

**E) Ответ функции:** в дополнение к `sent`/`failed` вернуть разбивку `per_bot: [{ bot_id, bot_username, sent, failed }]` — для отладки и подтверждения, что сообщения ушли с тех ботов, что выбраны.

### 2. `supabase/functions/email-mass-broadcast/index.ts`

Email рассылка — bot_ids неприменимы, ничего не трогаем (там нет ботов).

### 3. UI — без изменений

Чекбоксы выбора ботов в `BroadcastsTabContent.tsx` уже корректно формируют `filters.bot_ids` и передают их в payload. Поведение «основной по умолчанию» (пустой массив = primary) сохраняется.

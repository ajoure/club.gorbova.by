План:

1. Проблема

Сейчас есть два подтверждённых дефекта:

- UI: в `PromptFormDialog` реальная цепочка ограничения ширины всё ещё неполная, поэтому контент визуально упирается в правую границу и может давать некрасивый overflow.
- UX/логика: создание промпта жёстко требует `prompt_text`, из-за чего нельзя создать карточку с одной базой знаний или сначала загрузить материалы, а текст промпта заполнить позже.

2. Диагностика

По текущему коду:

- В `src/components/ai-chat/PromptFormDialog.tsx` сохранение заблокировано строками `if (!code.trim() || !title.trim() || !promptText.trim()) return;` и `const isValid = code.trim() && title.trim() && promptText.trim() && !responseFormatError;`.
- В `src/components/ai-chat/PromptAttachmentsSection.tsx` при `!promptId` секция вообще не даёт загружать файлы и показывает только текст “Сначала сохраните промпт...”.
- По скриншоту и структуре видно, что нужно добить не только строку вложения, но и контейнеры полей/секций, чтобы всё выглядело аккуратно “как в реквизитах/контактах”, без упирания в край.

3. Предлагаемое решение

Сделать add-only патч в двух файлах:

- `PromptFormDialog.tsx`
  - убрать обязательность `prompt_text`;
  - разрешить сохранение при валидных `code + title`, даже если текст промпта пустой;
  - улучшить layout секций и полей: гарантировать `overflow-x-hidden`, `min-w-0`, аккуратные grid/flex-ограничения, чтобы длинные тексты и select/input не вылезали за края;
  - при необходимости скорректировать сетку верхних полей на узкой ширине, чтобы `Тип` не прижимался к краю.
- `PromptAttachmentsSection.tsx`
  - сохранить полный overflow-chain для строки вложения;
  - довести визуал карточки вложения: аккуратные внутренние отступы, скругления, фон как в проекте, без вылезания имени/метаданных/кнопки;
  - заменить блок “сначала сохраните...” на сценарий, который не ломает новый UX создания: секция должна явно поддерживать поток “сначала сохранить карточку без текста, потом добавить файлы”, а не навязывать обязательный текст промпта.

4. Изменяемые компоненты

- `src/components/ai-chat/PromptFormDialog.tsx`
- `src/components/ai-chat/PromptAttachmentsSection.tsx`

5. Что не будет изменено

- `src/hooks/usePromptAttachments.ts` — логика safe storage key не меняется.
- База данных, bucket, backend-функции, extractor — вне scope.
- Общая архитектура AI-модуля и список типов промптов — без изменений.

6. Dry-run

Перед реализацией проверить в коде:

- все места, где `prompt_text` участвует в валидации создания/сохранения;
- все контейнеры внутри `PromptFormDialog`, где отсутствует `min-w-0`/`overflow-hidden`;
- что изменение не ломает edit-flow существующих промптов и не затрагивает загрузку вложений для уже созданных записей.

7. Execute

- Ослабить валидацию в `PromptFormDialog`: `prompt_text` сделать необязательным.
- Обновить `handleSave` и `isValid` так, чтобы карточка создавалась по `code + title`, а `prompt_text` мог быть пустой строкой.
- Довести layout диалога и карточек до стабильного состояния без горизонтального overflow.
- Подчистить UI секции вложений, чтобы строка файла, служебные метаданные и кнопка удаления всегда оставались внутри карточки и выглядели симметрично со всех сторон.

8. STOP-guards

Остановить внедрение, если:

- выяснится, что `prompt_text` обязателен на уровне БД или backend-логики создания;
- обнаружится ещё один source of truth для валидации промпта вне `PromptFormDialog`;
- для поддержки загрузки файлов “до текста промпта” потребуется менять не только UI, но и lifecycle создания сущности шире, чем текущий scope.

9. DoD

- Карточка/диалог визуально аккуратны со всех сторон: ничего не вылезает за края.
- В диалоге нет горизонтального скролла.
- Очень длинное имя вложения режется корректно и не ломает строку.
- Метаданные вложения (`размер • статус • символы`) не дают overflow.
- Создание промпта больше не требует заполненного `Текст промпта`.
- Можно создать карточку с пустым `prompt_text`, затем открыть её и загрузить базу знаний.
- Поведение редактирования существующих промптов не ломается.

10. Риски и зависимости

- Если в таблице `ai_user_prompts` поле `prompt_text` фактически not null без дефолта, одно только UI-изменение не закроет задачу.
- Если пользователь хочет загружать файлы буквально до первого сохранения записи, это уже отдельный flow (черновик/temporary id) и потребует более широкого патча. По текущему scope исправляется именно искусственное требование текста промпта, а не отсутствие `promptId` до создания записи.

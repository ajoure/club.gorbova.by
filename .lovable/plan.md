## Реальная причина «сайт обрезается»

`src/components/shared/HtmlIframePreview.tsx`, строка 31:

```ts
const MAX_IFRAME_HEIGHT = 15000;
```

И строка 511:

```ts
const clamped = Math.max(minHeight, Math.min(Math.ceil(raw), MAX_IFRAME_HEIGHT));
```

Высота iframe жёстко ограничена **15 000 px**. Длинные Tilda-лендинги (ЦБ 2.0 — это экспорт из Тильды) реально имеют высоту 25–60 тыс. px. Всё, что ниже 15 000 px, физически не показывается — низ страницы визуально «отрезан», хотя в БД он есть.

Это единственное место, где длинный HTML-контент реально обрезается на пути к пользователю.

## Что делаем

### 1. Поднять лимит высоты iframe

`src/components/shared/HtmlIframePreview.tsx`:

```ts
const MAX_IFRAME_HEIGHT = 200000; // было 15000
```

200 000 px = ~53 экрана FullHD — с многократным запасом под любые Tilda/HTML-лендинги, включая ЦБ 2.0. Полностью убирать защиту не будем — она страхует от runaway-контента (бесконечный `min-height` в кривом CSS), но 15k был слишком консервативным.

### 2. Явно задокументировать, что лимитов на сохранение НЕТ

Добавить короткий комментарий в `HtmlBlockEditor.tsx` над `<textarea>`:

```tsx
{/* Ограничений на размер контента нет: сохранение идёт напрямую в jsonb-колонку site_pages.blocks. */}
```

Чтобы будущие правки не начали добавлять `maxLength` «на всякий случай».

### 3. Верификация

- Открыть в превью страницу «ЦБ 2.0 из тильды» / «ЦБ 2.0 2026», убедиться, что скролл доходит до футера (форма/подвал/CTA).
- Через `psql` подтвердить, что `pg_column_size(blocks)` не изменился до/после — ничего не пересохраняем.

## Что НЕ трогаем

- Санитайзер `sanitizeHtml` — он не применяется к HTML-блоку (тип `html` рендерится в изолированный iframe без санитайза). Он работает только на inline text/columns/button. Не трогаем.
- Sandbox iframe (`allow-scripts allow-forms …`) — уже допускает всё нужное для Тильды. Не трогаем.
- Схема БД, миграции — не нужны.
- Backend/edge functions — не участвуют в сохранении блока, не трогаем.

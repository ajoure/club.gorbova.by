# PATCH — Унификация "квартира/офис" → "помещение" (ЮЛ/ИП) и "квартира" (физлица)

## Что делаем

Заменяем label и prefix `кв./оф.` → `пом.` для юридических лиц и ИП по всей платформе. Для физических лиц оставляем `кв.` / `Квартира`.

## Файлы и изменения

| Файл | Что меняем |

|------|-----------|

| `src/lib/address/formatStructuredAddress.ts` | `кв./оф.` → `пом.` в обоих функциях `formatBelarusAddress`, `formatGenericAddress`) |

| `src/components/shared/StructuredAddressBlock.tsx` | Label `Кв./Офис` → `Помещение` в `ADDRESS_SEGMENTS` и `COMPACT_SEGMENTS` (строки 42, 56). Для физлиц это же поле будет отдельно параметризовано в PATCH 6 |

| `src/components/ai-requisites/EntityRecordSheet.tsx` | Если в view-секции есть упоминание `кв./оф.` — заменить на `пом.` |

## Логика по типу субъекта

- **ЮЛ / ИП**: label = `Помещение`, formatter prefix = `пом.`

- **Физлица** (PATCH 6): label = `Квартира`, formatter prefix = `кв.`

В этом патче `StructuredAddressBlock` получает один universal label `Помещение`. В PATCH 6 при добавлении физлиц блок будет параметризован через prop (например `apartmentLabel`), чтобы для физлиц показывать `Квартира`.

## Formatter: итоговый формат адреса для Минска

```

ул. Советская, д. 10, пом. 5

220030, г. Минск

```

Нет — formatter возвращает одну строку: `220030, г. Минск, ул. Советская, д. 10, пом. 5`

Prefix `пом.` вместо `кв./оф.` — единственное изменение в formatter.

## DoD

- В formatter для ЮЛ/ИП используется `пом.` вместо `кв./оф.`

- В StructuredAddressBlock label поля = `Помещение`

- В EntityRecordSheet view-mode адрес показывает `пом.`

- Никаких изменений в БД (поле по-прежнему `apartment` в schema)

- Готовность к параметризации для физлиц в PATCH 6

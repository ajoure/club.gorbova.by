FIX — Скролл сбрасывается при навигации между страницами

## Корневая причина (найдена!)

`**ProtectedRoute**` — главный виновник. Каждый защищённый маршрут оборачивается в отдельный `<ProtectedRoute>`, который **ремаунтится** при каждой смене роута. При ремаунте:

1. `isInitializing = true` → **600ms спиннер** (вместо контента)
2. `isBanned = null` → **ещё спиннер** пока не придёт ответ от базы (~200-500ms)

Итого: **~600-1100ms** страница показывает спиннер вместо контента. За это время:

- `window.scrollY` = 0 (контента нет, скроллить некуда)
- `ScrollToTop` пытается восстановить позицию, но DOM слишком маленький
- Когда контент наконец рендерится, часть или все retry уже израсходованы

**Второй фактор**: `scrollRestoration = 'manual'` отключает встроенную браузерную восстановку, полагаясь целиком на наш код, который не успевает.

## План исправления

### 1. `src/components/layout/ProtectedRoute.tsx` — убрать задержки для повторных визитов

Проблема: 600ms `isInitializing` нужна только при **холодном старте** (первый рендер приложения), а не при переходе между страницами.

Изменения:

- Использовать **модульный флаг** `hasInitialized` (вне компонента) — после первого успешного рендера ProtectedRoute, пропускать 600ms задержку для всех последующих маунтов
- Заменить `useState(null)` для `isBanned` на **React Query** (`queryKey: ['user-banned', userId]`) — кеш переживает ремаунт, нет повторных запросов при навигации между страницами
- Пока `isBanned` в кеше → рендерить children сразу, без спиннера

### 2. `src/components/layout/ScrollToTop.tsx` — MutationObserver вместо фиксированных retry

Проблема: 15 retry × 150ms = 2.25 секунды — может не хватить при медленной сети, а при быстрой — лишние задержки.

Изменения:

- Использовать **MutationObserver** на `document.body` для отслеживания появления контента
- Когда `scrollHeight` достигает нужной высоты → мгновенно восстановить позицию
- Таймаут 5 секунд как fallback
- Сохранять позицию при `visibilitychange` (уход на другую вкладку браузера)

### 3. Не меняем

- Маршруты в App.tsx (слишком рискованная реструктуризация)
- Логику auth/consent
- Lazy loading
- Другие компоненты

## Влияние

- **Переход между страницами**: контент появляется мгновенно (без 600ms задержки) для уже авторизованных пользователей
- **Навигация назад (POP)**: скролл восстанавливается надёжно
- **Переключение вкладок браузера**: позиция скролла сохраняется
- **Первый заход**: поведение не меняется (600ms init сохраняется для холодного старта)

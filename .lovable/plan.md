## 2. Миграция 121000: поддерживаемый путь

- Инструмент отказывает потому, что файл пересоздаёт `invoke_sales_runtime_worker()`, а та читает `vault.decrypted_secrets`. Это блокировка платформы для агента, а не запрос «да/нет».
- Документированного владельцу интерфейса Lovable Cloud для применения такой миграции (SQL-редактор, кнопка подтверждения) нет: Cloud не даёт пользователю прямого доступа к базе, а штатный инструмент миграций подтверждения не предусматривает.
- Без обхода остаётся одно действие владельца: обратиться в поддержку Lovable (кнопка Help/Support в редакторе проекта). Нужно попросить применить точный GitHub-файл `20261009121000_sales_customer_conversations.sql` (SHA-256 `8b676963…`, main `e2f6c7bc…`) или разрешить применение для проекта. Дробить или переписывать SQL, использовать CLI/MCP/другой проект запрещено и не предлагается.
- Альтернатива, которую решает владелец и Codex (не Lovable): новый PR в GitHub, где пересоздание `invoke_sales_runtime_worker()` вынесено из 121000. Это изменение кода, поэтому только через GitHub-first и новую ревизию; сам Lovable его не делает.
- 122000 зависит от 121000 (новые колонки маршрута) и ставится только после неё. Развёртывание 4 функций PR613 тоже ждёт: новый код читает `sales_conversations.user_id`.

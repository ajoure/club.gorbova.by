# План: устранение двух оставшихся production-ошибок

Scope строго ограничен двумя записями. Ничего другого не трогаем: без кода, миграций, деплоя, Publish, платежей, provider-вызовов, сообщений, amoCRM.

## Проблема 1 — зависшая строка INV-25

Строка `payment_reconcile_queue` `0a8d8ad5-4305-405a-a75b-c33cdbe39bff`:
- `status = processing`, `source = webhook`, `attempts = 1`
- `created_at` 2026-08-02 13:45 UTC, `updated_at` 2026-08-02 18:00 UTC (возраст > 20 ч)
- канонический платёж по её `bepaid_uid` в `payments_v2` отсутствует

Строка застряла в промежуточном статусе: воркер её больше не подхватывает, а платёж не создан.

Шаги:
1. Read-only GET в bePaid по её uid — определить реальный статус транзакции (успешна / неуспешна / отсутствует).
2. Если транзакция неуспешна или отсутствует — одна CAS-транзакция: `processing → failed` с причиной в служебном поле, строго `WHERE id = ... AND status = 'processing' AND updated_at = <зафиксированный>`; ожидаемый rowcount = 1.
3. Если транзакция успешна — не создавать платёж вручную: вернуть строку в `pending` тем же CAS-условием, чтобы штатный воркер обработал её идемпотентно, и проверить результат через 1 цикл.
4. Запись в `audit_logs` (1 строка).
5. Read-back: INV-25 stale = 0.

## Проблема 2 — оплаченный заказ без доступа (ORD-26-02848)

Заказ `2a0e8e93-ee34-4ac5-bcd6-66d03b6ae6d8`, статус `paid`, 4500.00, платежи: один `succeeded` (25.07 13:40) и один `processing` (25.07 13:37). При этом:
- `access_grant_ledger` по заказу — 0 строк
- у пользователя нет ни одного entitlement и ни одной подписки

Это реальный оплаченный доступ, который не был выдан.

Шаги:
1. Диагностика read-only: правила выдачи по `product_id` / `tariff_id` (в т.ч. `access_delivery_mode` — не является ли доступ намеренно отложенным), логи `grant-access-for-order` за 25.07.
2. Если доступ должен быть немедленным — идемпотентный повторный вызов существующей функции `grant-access-for-order` строго для этого одного `order_id` (без изменения кода и без ручных INSERT в entitlements).
3. Если доступ по правилам отложенный — ничего не выдавать, зафиксировать классификацию и закрыть как ожидаемое поведение.
4. Отдельно проверить «висящий» платёж в статусе `processing`: только классификация, без изменений, если он дубликат успешного.
5. Read-back: по заказу появилась строка в `access_grant_ledger` и активный entitlement; INV-20 actionable остаётся 0.

## Стоп-правила

- Любое расхождение состояния с зафиксированным выше (статус строки/заказа/платежа изменился) — STOP и доклад.
- Никаких blind UPDATE/DELETE, только CAS с ожидаемым rowcount.
- Никаких provider write/cancel/charge/refund, писем и сообщений.
- UI не затрагивается, Publish не требуется.

## Definition of Done

- INV-25 stale = 0
- ORD-26-02848: доступ выдан либо документирован как штатно отложенный
- INV-20 actionable/orphan = 0, active-active groups = 0, orphan live links = 0
- По каждому изменению — запись в `audit_logs` и read-back

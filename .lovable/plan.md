План: E2E тестирование доступа к эфирам

**Цель:** Убедиться, что после последних изменений (`rule_kind='any_authenticated'`) эфир доступен только зарегистрированным пользователям, а анонимные — блокируются и перенаправляются на регистрацию.

### Diagnose (что уже известно)

- `live-resolve` требует Bearer-токен → без сессии возвращает `401 auth_required`.
- `LiveAccessEntry.tsx` → если сессии нет, редирект на `/auth?redirectTo=...`.
- Правило `any_authenticated` — новое, пускает любого залогиненного.
- Правило `product` — пускает только с активной подпиской/entitlement на связанный продукт.

### Plan (шаги теста через Playwright + браузер + Supabase)

**1. Подготовка тестовых данных (через миграцию БД)**

- Найти существующий эфир в `live_events` (или создать тестовый `Тестовый эфир — QA доступа`, статус `scheduled`, `starts_at` = now+1h, Kinescope-поля можно оставить пустыми — проверяем только gate).
- Создать 2 правила доступа в `live_event_access_rules` для одного и того же эфира:
  - **Эфир A** — `rule_kind='any_authenticated'` (открыт всем залогиненным).
  - **Эфир B** — `rule_kind='product'` + существующий product_id, к которому у тестового юзера нет доступа.
- Создать 2 тестовых аккаунта через `auth.admin.createUser` (edge-функция или SQL insert в `auth.users` через service_role невозможен из клиента → используем существующий приём: миграция + функция `create_test_user` уже есть в проекте; проверю). Аккаунты:
  - `qa_live_open@test.local` / пароль
  - `qa_live_locked@test.local` / пароль

**2. Тест-сценарии (Playwright, скриншоты на каждом шаге)**


| #   | Сценарий                                                                 | Ожидание                                                                        |
| --- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------- |
| T1  | Anon → `/live/<slugA>`                                                   | Редирект на `/auth?redirectTo=/live/<slugA>`, кнопка «Войти/Зарегистрироваться» |
| T2  | Логин `qa_live_open` → `/live/<slugA>` (правило `any_authenticated`)     | Доступ разрешён, страница эфира рендерится                                      |
| T3  | Логин `qa_live_open` → `/live/<slugB>` (правило `product`, подписки нет) | Блок «Нет доступа» / редирект на страницу продукта                              |
| T4  | Прямой вызов `live-resolve` без токена                                   | HTTP 401 `auth_required`                                                        |
| T5  | Прямой вызов `live-resolve` с токеном `qa_live_open` для эфира A         | HTTP 200 `status:ok`                                                            |

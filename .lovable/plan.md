План:

1. **Проблема**
  - В мобильной/PWA-версии раздела «Платежи» таблица и верхние табличные/статистические блоки ведут себя как вложенные скролл-зоны: появляется неудобный вертикальный скролл внутри страницы, горизонтальная прокрутка таблицы работает нестабильно, часть колонок/контента уходит за экран.
  - По симптомам это не только проблема одной таблицы: похожий риск есть в контактах, анкетах и других админских таблицах, где есть `overflow-x-auto`, `overflow-auto`, фиксированная высота или таблицы без детерминированной ширины.
2. **Диагностика**
  - Прочитан `docs/ENGINEERING_RULES.md`; задача выполняется как UI-only PATCH по порядку Diagnose → Plan → Dry run → Execute → Verify.
  - Проверены существующие компоненты и аналоги:
    - `src/components/layout/AdminLayout.tsx` — общий контейнер админки сейчас по умолчанию даёт `main overflow-y-auto`, а внутри страниц платежей/анкет есть ещё отдельный `overflow-auto`, что создаёт риск двойного вертикального скролла.
    - `src/components/layout/PullToRefresh.tsx` — корневой touch-контейнер имеет `touchAction: 'pan-y'`, из-за чего горизонтальные жесты внутри таблиц могут конфликтовать с нативной горизонтальной прокруткой на мобильных/PWA.
    - `src/index.css` — `.touch-scroll` сейчас использует `overscroll-behavior: contain`; это удерживает жести внутри вложенного скролл-контейнера и может мешать передаче вертикального скролла родителю.

3. **Предлагаемое решение**
  - Ввести единый UI-паттерн для мобильных табличных областей:
    - вертикально скроллит только основной контент страницы, без вложенного мобильного вертикального скролла таблицы;
    - таблицы получают собственный горизонтальный scroll-контейнер;
    - таблица имеет детерминированную ширину через сумму колонок/`colgroup`/`minWidth`, чтобы горизонтальная прокрутка была настоящей, а не «обрезанной»;
    - на мобильных блоки статистики становятся компактнее: горизонтальная лента карточек вместо высокой сетки 2x3;
    - touch-жесты разделяются: горизонтальный свайп внутри таблицы не блокируется Pull-to-refresh, вертикальный свайп прокручивает страницу.
  - Для админских hub-страниц с таблицами использовать `AdminLayout fullHeight` и один внутренний scroll-контейнер контента, чтобы убрать двойной вертикальный скролл.
  - Не менять данные, запросы, бизнес-логику, фильтры, сортировку, доступы, платежные действия и backend.

10. **Риски и зависимости**
  - Основной риск — `PullToRefresh`: изменение touch-action должно быть аккуратным, чтобы не сломать pull-to-refresh и вертикальный scroll.

  - Некоторые таблицы используют кастомные DnD/resize; их нельзя заменить новым компонентом без риска, поэтому правки будут локальными и совместимыми.

### Проблемы (наблюдаемые)

1. Клик по задаче открывает сразу редактор — режима просмотра нет.
2. Данные контакта (Клиент / Телефон / Email / Комментарий) впихнуты в поле «Описание» — уродливо и дублирует нормальные связи «Контакт»/«Сделка».
3. В блоке «Сделка» отображается «Без контакта 759fa191», хотя рядом в поле «Контакт» — «Тест Тестовый». Сделка не связана визуально с контактом.
4. Кнопка/имя контакта не открывает карточку контакта в этом же окне — нет удобного перехода к звонку.

### Что сделаем

#### 1. Двухрежимный диалог задачи

- Новый компонент `ViewCrmTaskDialog.tsx` — read-only «паспорт» задачи с крупной шапкой (тип-иконка, статус-бейдж, название), блоками «Описание», «Дедлайн / Напоминание», «Контакт», «Сделка», «Ответственный», «Результат/комментарий», аудит (создано/обновлено).
- В `AdminTasks.tsx` и во всех точках, где сейчас `EditCrmTaskDialog` открывается из канбан-карточки, списка и фильтров — по клику открывается **Просмотр**. В шапке просмотра — кнопка «Редактировать» (переключает на существующий `EditCrmTaskDialog`) и быстрые действия «В работу / Готово / Отменить».
- Существующий `EditCrmTaskDialog` не переписываем — оставляем как редактор; заголовок остаётся «Редактировать задачу».

#### 2. Контакт и сделка — как поля, а не в описании

- В `submit-lead-request/index.ts` убираем блок «Клиент/Телефон/Email/Комментарий», который принудительно приклеивается в `description`. Комментарий клиента (если есть) сохраняем в описании как «Комментарий клиента: …», остальное — из полей задачи (contact_id, order/deal) и `orders_v2.meta.contact_snapshot`.
- В карточке просмотра блок «Контакт» показывает: имя (кликабельно), телефон (кнопка «Позвонить» tel:), email (кнопка «Написать» mailto:), источник заявки. Данные берём из связанного `profiles` по `contact_id`, с фолбэком на `orders_v2.meta.contact_snapshot` (для старых лид-задач).
- Убеждаемся, что в orders_v2, созданных из lead-формы, `customer_name` заполняется (сейчас пишутся только email/phone) — добавим поле в insert, чтобы сделка «знала» контакт и в списке сделок не оставалась «Без контакта».

#### 3. Починка отображения «Сделка → Без контакта»

- В резолвере, который питает `TaskRelationsField` (`useTaskRelations` / RPC для сделок), `contact_name` берётся из полей заказа. Проверим, что для лид-заказа он резолвится по `profile_id` → `profiles.full_name`, а не только по `orders_v2.customer_name`. Правим либо RPC, либо клиентский маппинг, чтобы «Тест Тестовый» подтягивался.
- Дополнительно в insert из п.2 добавим `customer_name = effectiveName`, чтобы задним числом всё выглядело согласованно.

#### 4. Клик по контакту → ContactDetailSheet в том же окне

- В карточке просмотра имя контакта — `ClickableContactName` (уже есть) или встроенная кнопка, которая **не переходит на `/admin/contacts**`, а открывает `ContactDetailSheet` поверх (state в `AdminTasks`), используя хук по образцу `useLiveContactSheet` (lookup профиля по `contact_id`/`user_id`).
- Из шита контакта доступны стандартные действия «Позвонить/Написать/История» — пользователь получает «сразу позвонить клиенту», не теряя контекст задачи.

#### 5. Проверка (Playwright, dry-run)

- Создать лид-заявку с формы → открыть новую задачу в `/admin/tasks`:
  - карточка открывается в режиме просмотра;
  - описание не содержит блока «Клиент/Телефон/Email»;
  - «Контакт» = «Тест Тестовый», по клику открывается ContactDetailSheet поверх;
  - «Сделка» показывает «Тест Тестовый · <название продукта>», а не «Без контакта»;
  - кнопка «Редактировать» открывает существующий `EditCrmTaskDialog` без потери данных;
  - «В работу / Готово / Отменить» работают из режима просмотра.
- Скриншоты до/после прикладываем к отчёту.

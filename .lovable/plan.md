## 1. Кнопка «Открыть» в модалке Telegram — не активна

### Диагноз

`src/components/telegram/TelegramCompactCard.tsx`, ветка `pending` (строки 152–190):

```tsx
disabled={!linkSession?.deep_link}
```

`linkSession` — это **локальный** state внутри карточки, он появляется только после того, как пользователь сам нажал «Привязать» и клиент вызвал `startTelegramLink` (`handleStartLink`). Но статус `pending` может прийти и с сервера (`useTelegramLinkStatus` → RPC), если предыдущая сессия привязки ещё не истекла. Тогда:

- сервер отдаёт `status = 'pending'`;
- локального `linkSession` нет → `deep_link` пустой;
- ветка `pending` рендерится, но кнопка «Открыть» приходит уже отключённой без варианта что-либо сделать.

Именно это на скриншоте: карточка "Telegram" открыта, крестик активен, «Открыть» — синим-полупрозрачным = `disabled`.

Регрессия появилась после патча LeadRequestDialog (v3), потому что раньше при каждом открытии модалки состояние диалога полностью сбрасывалось и `TelegramCompactCard` монтировался «с нуля» после свежего вызова `startLink` — сейчас модалка сохраняет состояние и попадает в pending без локального `linkSession`.

### Правка

Только `src/components/telegram/TelegramCompactCard.tsx`:

1. При входе в ветку `status === 'pending'` без `linkSession` — автоматически (`useEffect`) вызвать `startLink.mutateAsync()`, чтобы получить актуальный `deep_link` для той же pending-сессии. Guard: одна попытка на монтирование (ref), чтобы не зациклиться, если сервер вернёт ошибку.
2. Дополнительно: если авто-регенерация упала или ещё идёт — показать кнопку «Получить ссылку», которая вызывает `handleStartLink` (не отключённую наглухо), а не «Открыть»-`disabled`. Тем самым пользователь всегда может сдвинуться с мёртвой точки.
3. Не трогать ветки `not_linked`, `inactive`, `active` — они и сейчас работают.

Никаких изменений на бэкенде и в `useTelegramLink` не требуется — контракт остаётся тем же.

## 2. Дубль блока «Индивидуальный договор» на `/ideologicheskaya-rabota`

### Диагноз

`site_pages.id = 7e672fed-13f1-4ff1-8786-71a228a0c011` содержит два блока:


| #   | id                                     | type      | что рендерит                                                                                                                                                                                                                                                                                                  |
| --- | -------------------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `3b63835a-f510-4cc8-992b-2de33b2b3f8c` | `html`    | Полный HTML лендинга. | 2   | `86b93087-16d5-4fcc-8e4c-32cf920c1b53` | `pricing` | Динамический pricing-блок React `TariffCard` для того же `product_id = 3ea08f79-...` и тех же трёх `tariff_ids`. Заголовок — «Индивидуальный договор». Это второй ряд карточек ниже основной секции.                                                                                                          |


Второй блок дублирует данные первого один-в-один (тот же продукт, те же тарифы) — именно его пользователь называет «белый Индивидуальный договор».

### Правка

Одна миграция на удаление конкретного элемента из `jsonb`-массива `blocks` по строгим ключам (id страницы + id блока), с явной проверкой, чтобы ничего лишнего не задеть:

```sql
UPDATE public.site_pages
SET blocks = COALESCE(
      (SELECT jsonb_agg(elem)
       FROM jsonb_array_elements(blocks) elem
       WHERE elem->>'id' <> '86b93087-16d5-4fcc-8e4c-32cf920c1b53'),
      '[]'::jsonb
    ),
    updated_at = now()
WHERE id = '7e672fed-13f1-4ff1-8786-71a228a0c011'
  AND EXISTS (
    SELECT 1 FROM jsonb_array_elements(blocks) elem
    WHERE elem->>'id' = '86b93087-16d5-4fcc-8e4c-32cf920c1b53'
      AND elem->>'type' = 'pricing'
  );
```

Идемпотентно (если запись уже удалена — UPDATE не сработает благодаря `EXISTS`), не трогает никаких других страниц и не удаляет продукт/тарифы/офферы — только сам pricing-блок со страницы.

### Проверка

## Технические детали (для инженеров)

- **Миграции**: одна миграция на структурные RPC/индексы (если понадобится `simulate_user_access` как SQL-функция); одна миграция на изменения `access_rules` (idempotent — `INSERT ... ON CONFLICT DO UPDATE` по `access_rules_unique_target`).
- **Симулятор**: `SECURITY DEFINER` SQL-функция + `SELECT`-права `authenticated` только для админов через `has_role`. В отчёте — использовать напрямую из миграционного/дискавери-скрипта, не открывая для клиента.
- **Backfill**: `INSERT ... ON CONFLICT DO NOTHING` в `entitlements`, `subscriptions_v2`, `telegram_access_grants`. Для `orders_v2.meta.deal_month` — `jsonb_set` только когда поле отсутствует и тариф месячный (period_label ∈ месячных, access_days ≈ 30).
- **Тестовые профили**: в `profiles` заводим с email `qa-access+…@lovable-test.local`, `is_test=true` (если поле есть; иначе пометка в `notes`). После симуляции — DELETE каскадом через FK.
- **RPC для симуляции**: подпереть уже существующим `has_month_purchase_bulk` — оно даст точный ответ, какой месяц открыт по какому тарифу.
- **Откат кода**: в `src/hooks/useMonthGate.ts` заменяем блок PATCH-…-V1 на предыдущую реализацию (bypass только для partial-правил без `match_purchase_month` + tariff-scoped gate). Все ссылки на `productMonthGate`/`productTariffs` удаляем.
- **Никакого хардкода UUID продуктов/тарифов** в коде и edge functions — вся конфигурация только в `access_rules`, `tariffs`, `products_v2`.

План: исправить ошибку дублирования кнопки оплаты

## Диагностика

При копировании offer (`handleCopyOffer` в `src/pages/admin/AdminProductDetailV2.tsx`, стр. 851–899) весь объект `meta` копируется как есть, включая поле `meta.slot_role`.

В БД существует частичный уникальный индекс:
```
tariff_offers_slot_role_per_tariff_uidx
ON tariff_offers (tariff_id, (meta->>'slot_role'))
WHERE NULLIF(meta->>'slot_role','') IS NOT NULL
```

Он гарантирует, что в рамках одного тарифа значение `slot_role` уникально. При копировании кнопки внутри того же `tariff_id` копия несёт то же `slot_role`, поэтому INSERT падает: `duplicate key value violates unique constraint "tariff_offers_slot_role_per_tariff_uidx"`.

Это чисто UX-баг копирования — не проблема схемы, индекс должен остаться.

## Исправление

В `handleCopyOffer` при формировании нового `meta`:

1. Клонировать `offer.meta` в локальный объект.
2. Удалить поле `slot_role` (роль в слоте страницы всегда должна быть уникальной в рамках тарифа; копия обязана быть без роли — админ при необходимости назначит роль вручную).
3. Оставить остальные поля `meta` (crm_routing, document_defaults и т.д.) — они не конфликтуют.
4. Сохранить существующую логику `is_active=false`, `is_primary=false`, отсутствие `getcourse_offer_id` и `(копия)` в button_label.

Также улучшить сообщение об ошибке: если Postgres вернул `23505` / текст со `slot_role_per_tariff_uidx`, показать понятный текст «Не удалось скопировать: у исходной кнопки задана роль в слоте, копия создана без роли/…» — но фактически такого не случится после фикса, поэтому оставим generic toast и один явный fallback.

## Файлы

- `src/pages/admin/AdminProductDetailV2.tsx` — только `handleCopyOffer` (несколько строк формирования `meta`).

Никаких SQL-миграций, изменений индекса, изменений типов, других компонентов.

## DoD

- Копирование любой кнопки в разделе «Кнопки оплаты» PRD-000039 (в т.ч. «Оплатить от ЮЛ» тарифа «Бухгалтер», где падало) создаёт неактивную копию без ошибки.
- Уникальный индекс `tariff_offers_slot_role_per_tariff_uidx` не тронут.
- Копия создаётся без `slot_role` в `meta`; остальная meta сохранена.
- Существующие offer-ы не затронуты, ничего не мигрируется.

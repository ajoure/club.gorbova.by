# План: Канонизация существующих FLD юр. лица + должность руководителя без склонения

Этот план **заменяет** предыдущую версию по двум пунктам: (1) ничего нового в registry не добавляем — используем уже существующие FLD; (2) должность руководителя жёстко мужского рода, склонение ФИО — независимо.

---

## 1. Канон трёх существующих FLD для юр. лица (заказчик / исполнитель / ИП)

### 1.1. Каноническая тройка для ЮЛ

Используем существующие FLD, ничего не создаём:

| FLD | Назначение | Текущий пример | Что должен возвращать резолвер |

|---|---|---|---|

| `FLD-000343` | Заказчик ЮЛ: Форма собственности | `ООО` | По умолчанию — короткая `ООО`). Модификатор «прописью» → `Общество с ограниченной ответственностью` |

| `FLD-000342` | Заказчик ЮЛ: Название | `ООО "Ромашка"` ❌ | Только название, без формы и без кавычек: `Ромашка` |

| `FLD-000345` | Заказчик ЮЛ: Краткое название | `ООО "Ромашка"` | Каноническая склейка: `ООО «Ромашка»` |

То же самое для исполнителя ЮЛ (симметричные FLD в группе «Исполнитель ЮЛ») и для ИП — там, где логически применимо (см. §1.3).

### 1.2. Модификатор «прописью» для FLD-000343 и симметричного исполнительского

- Добавляется в существующий механизм модификаторов FLD (тот же, что у падежей / `case_modifier`).

- Новый модификатор: `format='long'` (или `case_modifier='long_form'` — финальное имя в реализации).

- В UI каталога placeholder-ов `/admin/documents` → «Плейсхолдеры») в колонке «Настройки» в дропдауне рядом с «— без падежа» появляется опция «Прописью».

- Пример рендера итогового placeholder-а: `{{field:FLD-000343:long}}` → `Общество с ограниченной ответственностью`. Без модификатора → `ООО`.

- Словарь маппинга — фиксированный, контролируется кодом `ORG_FORM_SHORT_TO_FULL`): `ООО → Общество с ограниченной ответственностью`, `ЗАО → Закрытое акционерное общество`, `ОАО → Открытое акционерное общество`, `ИП → Индивидуальный предприниматель`, `УП → Унитарное предприятие`, `ЧУП → Частное унитарное предприятие`, `ОДО → Общество с дополнительной ответственностью`, `ТДО → Товарищество с дополнительной ответственностью`. Если short нет — пусто.

### 1.3. Что чинит резолвер (поведение трёх FLD)

`supabase/functions/_shared/typed-tokens-resolver.ts` для customer.leg / executor.leg:

- **FLD «Форма собственности»** `*.leg.org_form`)

  - Источник: `leg_org_form` (carrier) / `org_form` (executors). Если пусто — вытащить первое токен-слово из `leg_full_name` через `parseLegalEntityName`.

  - Дефолт-рендер: короткая форма `ООО`, `ЗАО`, `ИП` …).

  - С модификатором `long` — `ORG_FORM_SHORT_TO_FULL[short] ?? short`.

- **FLD «Название»** `*.leg.name`)

  - Источник: `leg_name` / `name`.

  - Очистка: убрать внешние кавычки `«…»`, `"…"`, `'…'`; убрать ведущий токен формы (если совпадает с `org_form`).

  - Результат: чистое имя без формы и без кавычек — `Ромашка`, `АЖУР инкам`.

- **FLD «Краткое название»** `*.leg.short_name`)

  - Каноническая склейка: `${org_form} «${name_clean}»`. Пример: `ООО «Ромашка»`, `ЗАО «АЖУР инкам»`.

  - Если `org_form` пусто — отдаём `«${name_clean}»`. Если оба пусто — пусто.

Никаких дополнительных FLD для ЮЛ не вводим. Поле `*.leg.full_name` (если уже используется в шаблонах) собираем как `${org_form_long} «${name_clean}»` без отдельного FLD — оно остаётся для backward-compat только в тех точках, где уже подвязано.

### 1.4. Приведение к канону «остальных» FLD юр. лица

Те же три FLD в группах «Исполнитель ЮЛ» и (где применимо) «ИП»:

- **Исполнитель ЮЛ** — симметрично FLD `*.leg.org_form / name / short_name` для executor. Если соответствующих FLD ещё нет в группе — НЕ создаём новые номера, а используем уже существующие в registry (нужно подтвердить из БД, см. §4).

- **ИП**: `org_form = "ИП"` (всегда фиксировано), `name` = ФИО предпринимателя (например, `Горбова Е. А.`), `short_name` = `ИП Горбова Е. А.` (без кавычек, поскольку это персона, а не наименование организации). Модификатор `long` на форме ИП → `Индивидуальный предприниматель`, итоговая `long`-склейка: `Индивидуальный предприниматель Горбова Е. А.`.

### 1.5. Что НЕ делаем

- Не создаём ни одного нового FLD.

- Не правим production-шаблоны автоматически.

- Не трогаем legacy alias-токены `{{customer.short_name}}` и т.п.) — они уже алиасятся на канонические.

- Не меняем UI компонента ввода реквизитов `OrganizationDetailsForm`) — он уже сохраняет `leg_org_form` и `leg_name` раздельно.

### 1.6. DoD по §1

- [ ] FLD-000343 без модификатора → `ООО`. С модификатором «Прописью» → `Общество с ограниченной ответственностью`.

- [ ] FLD-000342 → `Ромашка` (без формы, без кавычек). На реальной карточке «АЖУР инкам, ЗАО» → `АЖУР инкам`.

- [ ] FLD-000345 → `ООО «Ромашка»`, на «АЖУР инкам, ЗАО» → `ЗАО «АЖУР инкам»`.

- [ ] То же для исполнителя ЮЛ (симметричные FLD).

- [ ] ИП: `org_form='ИП'` (с long → `Индивидуальный предприниматель`), `name='Горбова Е. А.'`, `short_name='ИП Горбова Е. А.'`.

- [ ] В каталоге `/admin/documents → Плейсхолдеры` в строке FLD-000343 (и симметричной для исполнителя) в колонке «Настройки» появляется опция «Прописью» рядом с «— без падежа».

- [ ] Существующие шаблоны, которые используют FLD-000342/343/345, без правок шаблона начинают рендерить корректно (regression = улучшение).

## 2. Должность руководителя — без склонения по роду ФИО

### 2.1. Бизнес-правило

- Должность хранится и подставляется как есть в **мужском роде**, как ввёл пользователь: «Управляющий», «Директор», «Руководитель», «Юрист», «Консультант», «Главный бухгалтер».

- Род должности **никогда** не меняется в зависимости от пола ФИО руководителя.

- Падеж должности склоняется по контексту шаблона, но всегда по мужской парадигме: «Управляющий → Управляющего → Управляющему …». Никаких «Управляющая / Управляющей».

- ФИО руководителя склоняется самостоятельно, род определяется по отчеству (а не по фамилии).

Ожидаемые формы (родительный, «в лице …»):

- «в лице Управляющего Коврижкина Алексея Игоревича»

- «в лице Управляющего Коврижкиной Ольги Николаевны»

- «в лице Руководителя Федорчук Инны Григорьевны»

### 2.2. Изменения в коде

- `supabase/functions/_shared/ru-inflection.ts`:

  - В функции склонения должности `inflectPosition*`) убрать ветку `f-hint` / автоопределения женского рода по ФИО.

  - Жёстко передавать `gender='m'` для должности.

  - Добавить/расширить словарь мужских парадигм для типовых должностей: управляющий, директор, руководитель, юрист, консультант, бухгалтер, главный бухгалтер, заместитель, председатель.

- `supabase/functions/_shared/typed-tokens-resolver.ts`:

  - `*.director.position` (именительный) — возвращать как ввёл пользователь, только trim.

  - `*.director.position_*` (родительный/дательный/творительный/предложный) — вызывать инфлектор с фиксированным `gender='m'`.

  - ФИО руководителя `*.director.full_name` и падежные формы) — определять пол по отчеству `*ович/*евич/*ич → m`, `*овна/*евна/*ична → f`), склонять по реальному полу.

### 2.3. DoD по §2

- [ ] Тест-кейс «Управляющий + Коврижкин Алексей Игоревич» → во всех падежах должность мужская, ФИО — мужская парадигма.

- [ ] Тест-кейс «Управляющий + Коврижкина Ольга Николаевна» → должность мужская («Управляющего»), ФИО — женская парадигма («Коврижкиной Ольги Николаевны»).

- [ ] Тест-кейс «Руководитель + Федорчук Инна Григорьевна» → «Руководителя Федорчук Инны Григорьевны» (фамилия Федорчук в Р. п. ж. р. остаётся неизменной).

- [ ] Ни в одном кейсе не возникает «Управляющая / Управляющей / Управляющую».

- [ ] Unit-тесты `ru-inflection` покрывают 3 должности × 2 пола × 6 падежей.

## 2. Должность руководителя — без склонения по роду ФИО

### 2.1. Бизнес-правило

- Должность хранится и подставляется как есть в **мужском роде**, как ввёл пользователь: «Управляющий», «Директор», «Руководитель», «Юрист», «Консультант», «Главный бухгалтер».
- Род должности **никогда** не меняется в зависимости от пола ФИО руководителя.
- Падеж должности склоняется по контексту шаблона, но всегда по мужской парадигме: «Управляющий → Управляющего → Управляющему …». Никаких «Управляющая / Управляющей».
- ФИО руководителя склоняется самостоятельно, род определяется по отчеству (а не по фамилии).

Ожидаемые формы (родительный, «в лице …»):

- «в лице Управляющего Коврижкина Алексея Игоревича»
- «в лице Управляющего Коврижкиной Ольги Николаевны»
- «в лице Руководителя Федорчук Инны Григорьевны»

### 2.2. Изменения в коде

- `supabase/functions/_shared/ru-inflection.ts`:
  - В функции склонения должности (`inflectPosition*`) убрать ветку `f-hint` / автоопределения женского рода по ФИО.
  - Жёстко передавать `gender='m'` для должности.
  - Добавить/расширить словарь мужских парадигм для типовых должностей: управляющий, директор, руководитель, юрист, консультант, бухгалтер, главный бухгалтер, заместитель, председатель.
- `supabase/functions/_shared/typed-tokens-resolver.ts`:
  - `*.director.position` (именительный) — возвращать как ввёл пользователь, только trim.
  - `*.director.position_*` (родительный/дательный/творительный/предложный) — вызывать инфлектор с фиксированным `gender='m'`.
  - ФИО руководителя (`*.director.full_name` и падежные формы) — определять пол по отчеству (`*ович/*евич/*ич → m`, `*овна/*евна/*ична → f`), склонять по реальному полу.

### 2.3. DoD по §2

- Тест-кейс «Управляющий + Коврижкин Алексей Игоревич» → во всех падежах должность мужская, ФИО — мужская парадигма.
- Тест-кейс «Управляющий + Коврижкина Ольга Николаевна» → должность мужская («Управляющего»), ФИО — женская парадигма («Коврижкиной Ольги Николаевны»).
- Тест-кейс «Руководитель + Федорчук Инна Григорьевна» → «Руководителя Федорчук Инны Григорьевны» (фамилия Федорчук в Р. п. ж. р. остаётся неизменной).
- Ни в одном кейсе не возникает «Управляющая / Управляющей / Управляющую».
- Unit-тесты `ru-inflection` покрывают 3 должности × 2 пола × 6 падежей.

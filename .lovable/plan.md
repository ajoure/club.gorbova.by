## План правок урока «Шаг 3: Формирование внешнего продукта»

Все правки только в файле `src/components/lesson/blocks/ExternalProductWorkshop.tsx`. Логика данных (state shape, расчёты, сохранение) — не меняется, чтобы не сломать сохранённый прогресс учеников и admin-проф.

---

### 1. Блок 1 «Тип клиента»

- Подзаголовок: вместо «Определите типовой контур клиента, для которого вы собираете продукт» — **«Определите типовой контур клиента»** (убрать «для кого вы собираете продукт»).
- Убрать плейсхолдеры-комментарии в полях:
  - «Название типа» — плейсхолдер пустой (убрать «Напр.: ИП услуги без сотрудников»).
  - «Описание типа» — пустой (убрать «Как работает бизнес…»).
  - «Вывод по контуру» — пустой (убрать «Стандартный / сложный / нестабильный»).

### 2. Блок 2 «Сложность»

- Подзаголовок: **«Определите контур сложности»** (убрать «Контуры, которые увеличивают цену…»).
- Убрать строку подсказки `coeffHints` («1.0 — нет влияния · 1.2 — небольшое …»).
- Поле «Доплата, $» — переименовать ярлык в **«Коэффициент доплаты»**, убрать значок/суффикс «$».
- Перестроить порядок полей в карточке строки: **Название участка → Описание → Вывод → Коэффициент доплаты** (вместо текущего «Название/Коэффициент/Доплата + Описание + Вывод»).
- Убрать плейсхолдеры в полях (Название/Описание/Вывод).

### 3. Блок 3 «Сервис»

- Подзаголовок: **«Определите уровень включённости и взаимодействия»**.
- Убрать `coeffHints` («База 1.0 · Стандарт 1.3 · Премиум 1.6»).
- Убрать предзаполненные строки «База / Стандарт / Премиум» из `DEFAULT_STATE.service_levels` — пусть это будет одна пустая строка (как у complexity). Существующие сохранённые ответы останутся как есть (mergeState не перезаписывает заполненный массив).
- Тот же reorder полей: **Название уровня → Описание → Вывод → Коэффициент доплаты**, ярлык «Доплата, $» → «Коэффициент доплаты», без «$».
- Убрать плейсхолдеры.

### 4. Блок 4 «Ответственность»

- Подзаголовок: **«Определите границы ответственности»**.
- Убрать `coeffHints` («Ограниченная 1.0 · Расширенная 1.4 …»).
- Убрать предзаполненные строки «Ограниченная / Расширенная / Полная» из `DEFAULT_STATE.responsibility` — одна пустая строка.
- Тот же reorder полей и переименование «Доплата, $» → «Коэффициент доплаты», без «$».
- Убрать плейсхолдеры.

### 5. Блок 5 «Проверка цен по портфелю»

- Текст кнопки: вместо «Обновить из Шага 2» — **«Загрузить портфель из Шага 2»** (когда портфель уже импортирован — то же самое; единый текст).
- Гейтинг: блок 5 рендерится только когда блоки 1–4 заполнены (как минимум одно непустое название в каждом из четырёх массивов). Если нет — на месте блока 5 показываем мягкую подсказку: «Сначала заполните блоки 1–4 — затем загрузите портфель из Шага 2».
- Завершение шага (`completionValidation`) уже требует портфель + хотя бы один тип клиента — добавим проверку: непустое название хотя бы в одной строке каждого из 4-х справочников.

### 6. Футер

- Удалить текст: «Если ваши текущие клиенты не вписываются в продукт — проблема не в клиентах, проблема в модели. Продукт — эталон, клиенты — проверка.»
- Оставить только кнопку «Завершить Шаг 3» / Badge «Шаг завершён» + «Редактировать».

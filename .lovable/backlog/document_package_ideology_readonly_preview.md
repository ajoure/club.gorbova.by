# Backlog: read-only preview шаблонов для пользователя в пакете «Идеология»

## Контекст

В фазе 1 пакета «Идеология» (`/document-generation → Документы → Идеология`) для
read-only режима в `StrictDocumentTemplatesManager` через проп `readOnly=true`
скрыты ВСЕ мутационные элементы:

- кнопка «Загрузить .docx»;
- кнопка удаления (корзина);
- кнопка «Активировать версию»;
- кнопка «Разметить / Проверка и исправление плейсхолдеров»;
- весь правый preview-пейн целиком (вместе с валидационным статусом и кнопками
  «Скопировать плейсхолдеры», «Уже активен»).

В админке (`/admin/documents → Шаблоны документов`) при `readOnly` не передаётся —
поведение не изменилось, regression-proof снят 2026-05-25.

## Вопрос для follow-up

Нужен ли пользователю на `/document-generation → Документы → Идеология`
**view-only preview** карточки шаблона (без кнопок активации/удаления/разметки/
загрузки), чтобы он мог:

- увидеть имя файла активной версии, её дату и количество FLD-полей;
- (опционально) скачать активный `.docx` шаблон как ознакомительный;
- понимать состав пакета глубже, чем просто заголовок шаблона.

## Решение позже

Если ответ «да» — разделить в `StrictDocumentTemplatesManager` два независимых
флага вместо одного `readOnly`:

- `hideMutations: boolean` — скрывает «Загрузить», «Удалить», «Активировать»,
  «Разметить»;
- `hidePreview: boolean` — скрывает правый preview-пейн целиком.

Текущая фаза 1 эквивалентна `hideMutations=true` + `hidePreview=true`.
View-only режим = `hideMutations=true` + `hidePreview=false`.

Менять до явного решения по UX — нельзя (scope фазы 1 заморожен).
